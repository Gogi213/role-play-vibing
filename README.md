# Role Play Vibing

**Команда ИИ-ролей для Claude Code: владелец говорит с CEO, а работу делают Исследователь, Инженер и Судья — по тикетам, под присмотром диспетчера.**

## Зачем

Одна длинная сессия с ИИ копит контекст, теряет нить и встаёт, пока вы отошли. Role Play Vibing делит работу между ролями и ведёт её через тикеты: на каждую задачу — свой тикет и короткая сессия подходящей роли, а диспетчер сам будит следующего исполнителя.

- **Контекст не раздувается** — одна задача = один тикет = короткая сессия роли.
- **Работа не встаёт** — диспетчер будит роль, сторож ловит простои.
- **Алгоритм оптимальный** — узкое место → лучшие способы → замер на малом → боевой прогон.
- **Без упрощений ради кода** — упрощение только если замер доказал, что результат тот же.
- **Выводы проверены** — Судья принимает работу по договору «примут, если …».

Ядро работает на одной стандартной библиотеке Python: внешних пакетов и сервисов не нужно.

## Возможности

- **Диспетчер** (`dispatch.py`) — раз в 15 с читает тикеты и запускает роль (`claude -p`) или будит CEO; пределы параллельности по ролям, паузы между запусками, тормоза циклов, ротация сессий по размеру контекста, пауза до сброса лимита (429), учёт токенов.
- **Сторож** (`watch.py`) — следит, жив ли диспетчер, ищет тикеты-сироты, `blocked`, `needs_owner` и мёртвые цели ожиданий; сигналы пишет в `ceo-wake.log`.
- **Роли и тикеты** — CEO, Исследователь, Инженер, Судья; тикет — файл `.claude/tickets/TK-NNN.md` с шапкой и журналом; работа передаётся только через `--next`; с `reviewer: judge` исполнитель сдаёт по договору, Судья выносит вердикт по пунктам.
- **Хуки** — вставка роли, устава и команды тикетов в начале сессии, конспекты сессий и блокнот роли; **страж удаления** (`PreToolUse`) разрешает удалять и перезаписывать только внутри своей папки.
- **Сигналы CEO** — при шине сигнал идёт в очередь `ceo` с приоритетом, CEO читает её командой `tickets.py inbox`; при лежащей шине — запасной файл; [подробнее](docs/signals.md).
- **Ожидания `wait_for`** — тикет ждёт файл, другой тикет или задание на удалённой машине (`unit:`) и просыпается сам; [подробнее](docs/wait-for.md).
- **Шина событий** (необязательно) — HTTP и sqlite без внешних пакетов: конец задания будит диспетчера за секунды, а не на следующем тике; [подробнее](docs/bus.md).
- **Диспетчерская** — веб-табло: ход всех команд, шаги и вопросы владельцу, машины, лента событий; на компьютере и с телефона. Свою можно поднять самому; [подробнее](docs/dashboard.md).
- **Надёжность** — присмотр ОС за диспетчером и сторожем, счётчик простоя с SLO и тревогой, инвариант «у открытого тикета есть ход», прогон на выносливость; [подробнее](docs/reliability.md).
- **`/rpv-doctor`** — здоровье команды одной таблицей.
- **Выпуск, обновление, откат** — `release.py` меняет версию и тег, обновляет установленный плагин и возвращает прошлую версию одной командой; [подробнее](docs/release.md).

## Быстрый старт

1. Установите плагин в Claude Code:

   ```
   /plugin marketplace add https://github.com/Gogi213/role-play-vibing
   /plugin install role-play-vibing@role-play-vibing
   ```

2. В корне своего проекта выполните `/rpv-init` — команда создаст `.claude/roles` (уставы из шаблонов), `.claude/tickets` и строки в `.gitignore`. Существующие файлы не перезаписываются.
3. В основной сессии выполните `/ceo` — сессия получит роль CEO: с ней говорит владелец, она заводит тикеты.
4. Выполните `/rpv-start` — диспетчер и сторож запустятся в фоне; команда напечатает pid, пути логов (`<проект>/.claude/dispatcher/dispatch.run.log`, `watch.run.log`) и «отвязан: да/нет». Уже запущенные службы (pid-замок) команда останавливает и запускает заново: так подхватывается обновлённый плагин.
5. Поставьте задачу CEO и проверьте, что всё живо: `/rpv-doctor`.

Команда для заведения тикетов приходит CEO в начале сессии от хука (для сессии, помеченной `/ceo`, — из самой команды `/ceo`): `python "<плагин>/.claude/dispatcher/tickets.py" --project "<проект>" new …`.

## Установка

Нужно: Python 3.11 (только stdlib) и команда `python` в `PATH`, git, Claude Code CLI `claude` в `PATH` с выполненным входом. `ssh` и ключ — только если тикеты ждут задания на удалённых машинах (`wait_for: host:…`).

`/rpv-start` выбирает способ фонового запуска по ОС и отвязывает службы от сессии: закрытие окна Claude их не останавливает.

| | Windows | macOS | Linux |
|---|---|---|---|
| Запуск `/rpv-start` | WMI `Win32_Process.Create` | `Popen` в новой сессии | `systemd-run --user`; без systemd — как на macOS |
| Переживает закрытие Claude | да | да | да |
| Переживает перезагрузку | нет | нет | нет |
| Автозапуск после входа или перезагрузки | вручную `/rpv-start` | LaunchAgent | постоянный user-юнит systemd |
| Подробности | [Windows](docs/install-windows.md) | [macOS](docs/install-macos.md) | [Linux](docs/install-linux.md) |

Требования, ручной запуск, поиск корня проекта и таблица платформ целиком — [docs/install.md](docs/install.md). Присмотр, который сам поднимает упавшие службы, — [docs/reliability.md](docs/reliability.md).

<details>
<summary>Запуск вручную, без <code>/rpv-start</code></summary>

Скрипты работают прямо из папки плагина (`<плагин>` — каталог установленного плагина, `${CLAUDE_PLUGIN_ROOT}`), копировать ничего не нужно:

```
python <плагин>/.claude/dispatcher/start.py --project <проект>      # то же, что /rpv-start
python <плагин>/.claude/dispatcher/dispatch.py --project <проект>
python <плагин>/.claude/dispatcher/watch.py --project <проект>
```

Корень проекта — `--project`, иначе `RPV_PROJECT`, иначе `CLAUDE_PROJECT_DIR`, иначе ближайший каталог вверх от текущего с `.claude/roles`; не нашли — ошибка с подсказкой `--project` / `/rpv-init`, каталоги не создаются. Состояние (`state.json`, логи, `ceo-inbox.md`, `ceo-wake.log`) лежит в `<проект>/.claude/dispatcher/`; тикеты и роли — в проекте.

## Как это работает

| роль | делает | сессия |
|---|---|---|
| CEO | говорит с владельцем, заводит тикеты, читает сигналы | долгая |
| Исследователь | протокол → счёт → отчёт | на тикет |
| Инженер | код, тесты, машины | на тикет |
| Судья | проверка и вердикт | на тикет |

Поток работы: владелец → CEO → тикет → диспетчер → роль → Судья → CEO → владелец.

1. Владелец ставит задачу CEO, CEO заводит тикет `.claude/tickets/TK-NNN.md`; диспетчер `dispatch.py` запускает роль.
2. Роль сдаёт итог шага: `tickets.py result <ID> <done|pr|accept|return|blocked|ask-owner|wait> --why "…"` (запись в журнал
   тикета ставит сама команда; `comment` — только промежуточная заметка).
3. Кого будить дальше — решает таблица маршрутов (`routes.py`): диспетчер будит следующую роль; с `reviewer: judge` работу
   принимает Судья по договору.
4. Сторож `watch.py` пишет сигналы в `ceo-wake.log`.
5. CEO отвечает владельцу.

Статусы тикета, остановка роли (`tickets.py stop`) и переменные диспетчера описаны в [`.claude/dispatcher/README.md`](.claude/dispatcher/README.md).

**Правила команды**

- Только оптимальный алгоритм; в отчёте строка «Алгоритм: …».
- Данные и модель — как в реальности.
- Новые задачи — только по слову владельца.
- Числа владельцу — после Судьи; оценка ≠ замер.
- Передача работы — только `--next`.
- Удаление — только внутри проекта.
- Судью не снимает CEO: он единственный кросс-аудитор и валидатор качества; снять его может только владелец прямой цитатой.

Полный устав — [`templates/roles/README.md`](templates/roles/README.md) (`/rpv-init` копирует его в `.claude/roles/README.md` проекта).

## Команды

| команда | назначение |
|---|---|
| `/rpv-init` | Подготовить проект: `.claude/roles` из шаблонов плагина, `notes/`, `tickets/`, строки в `.gitignore`; существующее не перезаписывает |
| `/ceo` | Пометить сессию как CEO (метку читают хуки; роль держится и после `/clear` в Desktop) |
| `/rpv-start` | Запустить или перезапустить диспетчер и сторож в фоне; при заданном `RPV_BOARD` — ещё и отправку сводки на табло |
| `/rpv-doctor` | Здоровье команды одной таблицей: диспетчер, сторож, присмотр ОС, шина, очередь, ошибки за сутки; только читает |

Скрипты плагина (запускаются из его папки, `--project <проект>`):

| скрипт | назначение |
|---|---|
| `dispatcher/tickets.py` | тикеты: `new`, `comment`, `start`, `stop` (только CEO), `wait`, `status`; `inbox [--peek]` — очередь сигналов CEO |
| `dispatcher/supervise.py` | присмотр ОС за диспетчером и сторожем: `--install` / `--uninstall` |
| `dispatcher/release.py` | выпуск, обновление, откат: `bump`, `update`, `rollback`, `check` |
| `dispatcher/board_push.py` | сводка команды на табло и в `.claude/pulse/status.json` |
| `dispatcher/endurance.py` | прогон на выносливость |
| `bus/busclient.py` | отправка события в шину: `send <адрес>` |

## Настройка

Переменные окружения `RPV_*`; для службы они переносятся при запуске через `/rpv-start`. Главные:

| переменная | по умолчанию | смысл |
|---|---|---|
| `RPV_PROJECT` | — | корень проекта (если не задан `--project`) |
| `CLAUDE_BIN` | `claude` из `PATH` | путь к Claude Code CLI |
| `RPV_DISPATCH_INTERVAL` | `15` | тик диспетчера, с |
| `RPV_DISPATCH_MAX_PARALLEL` | `3` | сколько запусков ролей одновременно |
| `RPV_DISPATCH_ROLE_PARALLEL` | пусто (по одному на роль) | предел по ролям, `engineer:3,researcher:1` |
| `RPV_DISPATCH_TIMEOUT` | `1200` | таймаут запуска роли, с |
| `RPV_DISPATCH_MODEL` | `claude-sonnet-5-5` | модель ролей |
| `RPV_DISPATCH_ROLE_MODEL` | Судья — `claude-opus-5-5`, остальные — `RPV_DISPATCH_MODEL` | модель по ролям, `judge:…,engineer:…` или одно значение на все |
| `RPV_DISPATCH_EFFORT` | Судья `xhigh`, Инженер и Исследователь `high` | усилие по ролям; в тикете перекрывается полем `effort` |
| `RPV_DISPATCH_ROTATE_TOKENS` | `120000` | контекст, после которого сессия роли начинается заново |
| `RPV_WATCH_INTERVAL` | `120` | цикл сторожа, с |
| `RPV_WATCH_NO_PLAN_MIN` | `30` | через сколько минут «в работе без плана шагов» или «шаги на табло не менялись» сторож пишет роли в тикет и будит её |
| `RPV_WATCH_PLAN_LAG_MIN` | `5` | допуск: запись роли в логе не считается «новее плана», если позже обновления шагов меньше чем на столько минут |
| `RPV_WATCH_ORPHAN_HOURS` | `2` | через сколько часов без записи тикет считается сиротой |
| `RPV_IDLE_SLO_MIN` | `10` | допустимый простой, минут в сутки |
| `RPV_BUS_URL` | не задан — шина выключена | адрес шины событий |
| `RPV_BUS_TOKEN` / `RPV_BUS_TOKEN_FILE` | — / `~/.rpv-bus-token` | токен шины: значением или файлом |
| `RPV_BOARD` | не задан | строка подключения к Диспетчерской из окна «+» |
| `RPV_MACHINES` | не задан | машины для табло: `pc2=user@host,srv=алиас` |
| `RPV_PLAIN` / `RPV_PC` | `1` / `1` | человеческие строки процессов (Haiku) / загрузка «этого ПК»; `0` — выключить |
| `RPV_CALC_HOST` / `RPV_VPS_HOST` / `RPV_DECK_HOST` | не заданы | хосты для `wait_for: host:<calc\|vps\|deck>:…` и ssh-проверок (`user@host` или алиас из `~/.ssh/config`) |
| `RPV_DECK_KEY` / `RPV_DECK_KNOWN_HOSTS` | — | ключ ssh и файл known_hosts |
| `RPV_GUARD_REMOTE_ROOTS` / `RPV_GUARD_HOST_ROOTS` / `RPV_GUARD_STAGE` / `RPV_GUARD_FORBIDDEN_HOSTS` | не заданы — на удалённых машинах удалять нельзя нигде | страж удаления: разрешённые каталоги на удалённых машинах (`хост=корень,корень;хост2=…` — только при ssh на этот хост), стадия, закрытые хосты |

Все переменные с пояснениями и значениями по умолчанию — [docs/configuration.md](docs/configuration.md).

Прочее:

- **Сессия CEO** — команда `/ceo` (метка сессии); запасной путь — слово `CEO` в названии сессии Claude Desktop.
- **Роли и зоны** — уставы и ссылки в `.claude/roles/*.md` проекта.
- **Хуки** запускает `hooks/run-hook.sh`: `python3`, иначе `python`, иначе `py -3`; в проекте без `.claude/roles` хуки молчат. Страж удаления ловит Bash, PowerShell, Write, Edit, MultiEdit и NotebookEdit (`hooks/hooks.json`); корень проекта — `CLAUDE_PROJECT_DIR`.
- **Проверки второй машины** (сторож, ssh) выключены, пока не задан `RPV_DECK_HOST`; пустой файл `<проект>/.claude/dispatcher/deck-off` выключает их и при заданном хосте.

## Диагностика

`/rpv-doctor` печатает таблицу `OK / WARN / FAIL / —`: диспетчер и сторож (pid жив, возраст сердцебиения), присмотр ОС, шина, очередь тикетов по статусам, тикеты `waiting` без условия, запуски не `ok` за сутки, сегодняшний простой. Команда только читает; код возврата 1 — есть FAIL, 2 — проект не найден, `--json` — машинный вид.

Диспетчер каждый тик учитывает **счётчик простоя** (`state.json` → `downtime`): минуты в сутки, когда есть готовая работа без исполнителя, роль ждёт без условия (дольше 10 мин) или диспетчер молчит при работе. Превышение `RPV_IDLE_SLO_MIN` — одна тревога в сутки: событие шины `служба.простой.превышен` → CEO (шины нет или она недоступна — строка `idle-slo` в `ceo-inbox.md`).

Службы не запущены — `/rpv-start`; присмотра нет — `python <плагин>/.claude/dispatcher/supervise.py --install`. Подробнее — [docs/reliability.md](docs/reliability.md).

## Разработка и тесты

```
python -m pip install pytest
python -m pytest .claude -q
```

Или без pytest — `python -m unittest discover -s .claude/dispatcher`, затем то же для `-s .claude/hooks`, `-s .claude/board` и `-s .claude/bus`.

- **CI** — workflow [`ci`](.github/workflows/ci.yml): тесты на Windows, macOS и Linux × Python 3.11–3.13 на каждый PR и каждый push в `main`; итоговая проверка `ci-ok`.
- **Выносливость** — workflow [`endurance`](.github/workflows/endurance.yml) каждую ночь и вручную: настоящий диспетчер, фейковые роли и сбои (падение шины, убитый диспетчер, лимит 429); критерий — 0 потерянных сигналов, 0 `blocked`, простой не больше порога. Локально: `python .claude/dispatcher/endurance.py --rounds N` (или `--hours H`; ещё `--idle-max S`, `--seed K`, `--keep`, `--modes`) — [docs/reliability.md](docs/reliability.md#прогон-на-выносливость).
- **Версии** — `python .claude/dispatcher/release.py check` проверяет, что версии в `plugin.json`, `marketplace.json` и `CHANGELOG.md` совпадают.

Структура репозитория:

```
commands/            слэш-команды плагина
agents/              помощники ролей: coder, reader
hooks/               hooks.json и запускатель хуков
templates/roles/     уставы ролей — копируются в проект командой /rpv-init
.claude/dispatcher/  диспетчер, сторож, тикеты, doctor, присмотр, выпуск
.claude/bus/         шина событий, сторож машины, клиент
.claude/board/       сервер и страница Диспетчерской, машины, TUI и MCP
.claude/hooks/       страж удаления, страж сигналов CEO, контекст и память ролей
docs/                подробные инструкции
```
