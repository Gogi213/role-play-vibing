# Role Play Vibing

Команда ИИ-ролей для Claude Code: ты говоришь с одним CEO, а работу делают Исследователь, Инженер и Судья по тикетам —
без потери контекста и без простоев.

Комплект выгружен из проекта alpha, где он отработал в бою (диспетчер, сторож, хуки, устав ролей). Рабочие файлы лежат
как есть; личное (хосты, домашний путь) заменено плейсхолдерами `<HOST_...>` и `<HOME>`.

## Какие проблемы решает

- **Один чат раздувается и забывает** — исполнители живут короткими сессиями, одна задача — один тикет; нужное лежит в
  тикете и блокноте роли.
- **Работа встаёт, пока никто не смотрит** — диспетчер сам будит нужную роль по статусу тикета, сторож без модели
  следит за диспетчером и зависшими тикетами и пишет CEO только по находке.
- **ИИ берёт первый попавшийся способ** — правило «оптимальный алгоритм»: найти узкое место, перебрать лучшие способы,
  замерить на малом, и только потом боевой прогон; в отчёте тикета строка «Алгоритм: …».
- **Данные и модель упрощают ради кода** — правило «как было, без упрощений»: упрощать можно, только если замер
  доказал, что результат не меняется.
- **Выводы без проверки** — Судья с договором «примут, если …» проверяет живой результат и пересчитывает ключевые числа.
- **Дорогой контекст** — хук просит клир сессии CEO от порога токенов; траты считаются, потолок стоит на один запуск.

## Роли

| роль | что делает | сессия |
|---|---|---|
| CEO | говорит с владельцем, заводит тикеты по его слову, ведёт состояние проекта, читает сигналы сторожа; сам не считает и не пишет код | долгая |
| Исследователь | вопрос, протокол до счёта, счёт по протоколу, отчёт с шумом и числом испытаний | на тикет |
| Инженер | код, сборки, тесты, скрипты, машины; ускорение принимается только по воротам «результат тот же» | на тикет |
| Судья | проверяет договор и живой результат, выносит вердикт таблицей; сам результат не ищет | на тикет |

## Как работает

1. Владелец говорит CEO, что нужно; CEO заводит тикет `.claude/tickets/TK-NNN.md` (`tickets.py new …`).
2. Диспетчер (`dispatch.py`, цикл раз в 15 с) видит `status: todo` и запускает владельца тикета: `claude -p …` с уставом
   роли (его подставляет хук `role_context.py`).
3. Роль работает и пишет итог только в лог тикета: `tickets.py comment <ID> --author <роль> --text "…" [--next <роль>]`.
4. `--next judge` (или другая роль) — диспетчер будит её один раз; `--next ceo`, статусы `blocked` / `needs_owner` /
   `done` — одна строка в `ceo-inbox.md` и `ceo-wake.log`.
5. Сторож (`watch.py`, без модели) раз в 2 минуты проверяет, что диспетчер жив, нет зависших тикетов и тревог; пишет
   CEO только по находке и отмечает сердцебиение.
6. CEO держит `Monitor` на `ceo-wake.log` и отвечает владельцу: результат и число первыми, потом смысл и следующий шаг.

## Правила команды

Полный текст — `.claude/roles/README.md`; роли — `ceo.md`, `researcher.md`, `engineer.md`, `judge.md`.

- Только оптимальный алгоритм (см. выше); данные и модель — как в реальности.
- Новые задачи — только по слову владельца; состояние задачи — только в тикете.
- Числа владельцу — после Судьи; оценка — не замер, допущение называется допущением.
- Передать работу — только `--next <роль>`; `@упоминания` в тексте никого не будят.
- Удаление — только внутри своей папки (`delete_guard.py`); коммит — только своих файлов.

## Установка

```
/plugin marketplace add https://github.com/Gogi213/role-play-vibing
/plugin install role-play-vibing@role-play-vibing
```

Плагин подключает хуки (`hooks/hooks.json`, через `${CLAUDE_PLUGIN_ROOT}`) и агентов `coder` и `reader`. Диспетчер,
сторож и тикеты определяют корень проекта по своему расположению, поэтому для работы скопируйте каталоги из плагина
(`~/.claude/plugins/cache/role-play-vibing/…`) в свой проект: `.claude/dispatcher`, `.claude/roles`, `.claude/hooks`,
`.claude/tickets`. Команды запуска и работы с тикетами — `.claude/dispatcher/README.md`, раздел «v2».

## Что поправить под свой проект

- **Хосты в `watch.py` и `dispatch.py`** — вторая машина для ssh-проверок: `ALPHA_DECK_HOST`, `ALPHA_DECK_KEY`,
  `ALPHA_DECK_KNOWN_HOSTS` (умолчания — плейсхолдеры `<HOST_DECK>`, `<HOME>`). Второй машины нет — создайте пустой файл
  `.claude/dispatcher/deck-off`, и сторож не будет ходить по ssh.
- **Название сессии CEO** — роль CEO определяется по названию сессии Claude Desktop: назовите сессию так, чтобы в
  названии было `CEO`. Остальные роли получают `ALPHA_ROLE` от диспетчера.
- **Устав и зоны** — `.claude/roles/*.md`: зоны каталогов, ссылки на файлы состояния проекта, модели и усилие
  (`dispatch.py`: `CLAUDE_MODEL`, `ROLE_MODEL`, `ROLE_EFFORT`).
- **Защита удаления** — константы `LOCAL_ROOTS`, `REMOTE_ROOTS`, `STAGE`, `FORBIDDEN_SEG`, `BOX_RE`, `REASON` в
  `.claude/hooks/delete_guard.py`; хук подключается в `PreToolUse` для Bash/PowerShell, вызывая `check(cmd, cwd)`.
- Нужны Python 3.11 (только stdlib), Claude Code CLI `claude` в `PATH`, git. Диспетчер запускает роли с
  `--permission-mode bypassPermissions`: защита — `delete_guard`, потолок запуска и устав.
