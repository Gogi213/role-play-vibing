### Добавлено
- **Сигнал `watch-unreleased`: «влито, не выпущено» при пустой очереди (TK-062, PR #173, В-24).** Сторож будит CEO, когда тикетов в работе (`todo`, `in_progress`, `in_review`, `waiting`, `blocked`, `needs_owner`) нет дольше 10 мин, а у GitHub в `main` репозитория `ci_repo` есть коммиты после последнего тега `v*` (старший по номеру; локальный `main` не смотрится). Повтор — раз в сутки, пока не выпущено; нет `ci_repo` или GitHub не ответил — молчит. Включается `tickets.py config set watch_unreleased true`, по умолчанию выключен. Код — новый модуль `unreleased.py`, вызов из `watch.run_once` одним циклом с проверкой сирот.
- **Правило устава CEO «покрыто решением — делай, не спрашивай» (TK-062, В-24).** `templates/roles/ceo.md`: прежде чем спросить владельца, CEO сверяет реестр; если действующее решение В-N цитатой прямо называет это действие (например, выпуск после приёмки Судьи), сразу заводит тикет со ссылкой `--ref В-N`. «Похожее» решение не в счёт; деньги, необратимое, направление и бизнес-правило — по-прежнему владельцу; публикация — `allow <ID> publish --ref В-N`.
- **Правило устава CEO «наблюдение держишь всегда» (TK-062, В-24).** `Monitor` на `ceo-wake.log` живёт до 30 мин, и сигнал в истёкший `Monitor` никого не будит; CEO перевзводит наблюдение сразу при «Monitor expired» и после рестарта сессии и не обещает «напишу, когда …», пока оно не включено. `/ceo` (`commands/ceo.md`) теперь сам взводит `Monitor` (в `allowed-tools` добавлен `Monitor`).

### Документы

### Добавлено

Команда ярлыков «тест» и «запуск» — в тех же рамках, что у проверок ошибок (`errors.py fix`); приёмка Судьи (`tickets.py accept`) гоняет её в копии тикета `.claude/worktrees/<ID>`, код выхода не 0 или ярлык без команды — отказ. Договор без ярлыков принимается как раньше. Код — новый модуль `tickets_proof.py`; в шаблонах уставов Судьи, Инженера и Исследователя — строки о ярлыках.
- **Порог контекста сессии CEO: вставка с 350 тыс., хардстоп с 400 тыс. токенов (TK-052, PR #163, В-15).** Хук `hooks/ceo_context.py` считает контекст по последнему ответу сессии (вход + кэш). С `ceo_context_warn` (умолчание `350000`) на каждое сообщение владельца CEO получает вставку «допиши блокнот и попроси `/clear`»; с `ceo_context_stop` (`400000`) сообщение в модель не уходит — владелец видит причину и слово `/clear`. `/clear` и `/compact` проходят всегда. Ключи задаются `tickets.py config set`; значение не целое ≥ 1 или `warn` ≥ `stop` — оба ключа берутся по умолчанию. Другие роли и запуски диспетчера не затронуты.
- **Помощник `critic` и правило CEO «рекомендация владельцу — только после критика» (TK-053, PR #164, В-17).** `agents/critic.md` — читает сырьё (записи тикетов, `runs.log`, файлы, `git`), сверяет каждое утверждение предложения и отвечает по пунктам «держится» / «не держится» / «не хватает» с `файл:строка`, затем исправленной формулировкой и строкой «Изменилось: да | нет»; модель Sonnet, инструменты `Read`, `Grep`, `Glob`, `Bash` (только чтение). В уставе CEO (`templates/roles/ceo.md`) — строка: предложение или починка владельцу уходят после разбора критика, с одной строкой «Критик: проверил … — изменилось …». Ответ без рекомендации (статус, факт) критика не требует.
- **Флаг `hold_alive_waits` — не будить роль на `waiting`, пока задание живо (TK-054, PR #165, В-18).** Включён (умолчание, `tickets.py config set hold_alive_waits false` — выключить): роль на `waiting` с невыполненным `wait_for` не запускается ни по `next:`, ни по просрочке срока, пока сторож видит задание живым — юнит или процесс с именем задания, задание тикета в адаптере (`running` / `queued`). Срок `--by` при живом задании будит не раньше чем через 12 ч после срока. Отметка живости — `wait-alive.json`, старше 15 минут она не действует. Раз в 60 минут при сдвиге прогресса сторож пишет в тикет строку «жив, N из M, ETA» кодом, без модели. `false` возвращает прежнее поведение (срок `--by` будит роль и при живом задании); ошибку E-009 (при `false` срок всё равно удерживался) Судья нашёл и исправил до выпуска (27bf8a6) — в 2.0.11 её не было.

### Изменено (CP1, реестр ошибок)
Четыре обхода реестра, найденные ревью (критерий 7, «ошибка не повторяется»):
- `errors.py fix` объявляет исправленной только Судья (`RPV_ROLE=judge`) или сессия без `RPV_ROLE` (CEO, владелец); `researcher`, `engineer` и любая другая роль получают отказ «исправленной ошибку объявляет Судья: `tickets.py result …` с указанием проверки». `add`, `run`, `show`, `list` — по-прежнему любой роли. Несовместимо: инженер и исследователь больше не закрывают ошибку сами — называют проверку в итоге (`result … --why`), `fix` запускает Судья.
- Красный → зелёный: `fix` требует, чтобы проверка проходила сейчас (в `--cwd` или корне проекта) и НЕ проходила на коммите «до исправления». Коммит «до» — `--before <коммит>`, иначе отметка `added_sha`, которую `add` теперь пишет в шапку записи (HEAD проекта на момент заведения). Прогон «до» — во временном `git worktree add --detach` в каталоге ОС (потом `worktree remove --force`); файлы проверки (скрипт или тесты из `--check`, в т. ч. модуль `пакет.модуль.Класс.тест` и каталоги) копируются туда из текущего дерева — новая проверка, которой на старом коммите нет, иначе «падала» бы от отсутствия файла, а не от ошибки. Проверка зелёная и «до» — отказ «проверка не ловит ошибку: на <коммит> она уже зелёная»; нет ни `--before`, ни `added_sha` (записи до 2.0.0) — отказ с подсказкой `--before`; не git-репозиторий — отказ. Файлы проверки в `fix` должны быть закоммичены (`fixed_sha` — коммит, где они лежат в проверенном виде).
- Проверку исправленной ошибки нельзя ослабить в своей ветке: `run` и приёмка Судьи (`gate`) перед запуском каждой проверки сверяют её файлы в каталоге запуска (worktree тикета) с отпечатком `check_hash`, снятым при `fix` (см. ниже); записи без отпечатка — с версией на `fixed_sha` (`git show` из корня проекта). Концы строк не в счёт. Отличается или удалён — FAIL «проверка изменена после исправления — менять её можно только через Судью (`errors.py fix` заново)», проверка не запускается. Править проверку законно через повторный `fix` Судьи: он двигает `fixed_sha` и снимает отпечаток заново. Проверку держи в отдельном файле: правка соседних тестов в том же файле тоже требует повторного `fix`.
- Сверка проверки больше не пропускается тихо, когда коммит `fixed_sha` пропал (rebase + gc): `fix` пишет в шапку записи `check_hash` — отпечаток содержимого каждого файла проверки (JSON `{путь: sha256}`, концы строк приведены к LF; для цели-каталога — все отслеживаемые файлы под ним). `run` и приёмка (`gate`) сверяют файлы в каталоге запуска с этим отпечатком — git и коммит не нужны. Записи без отпечатка (исправлены до 2.0.1; повреждённое поле считается отсутствующим) — как прежде, через `git show <fixed_sha>`; а если нет и коммита (`fixed_sha` пуст или пропал из репозитория) — FAIL «проверка исправленной ошибки не сверена: нет ни отпечатка, ни коммита — Судья, `errors.py fix` заново», проверка не запускается. Пропуск с пометкой в `run` остался только для записи без отпечатка, у которой коммит на месте, а файла проверки на нём нет. Недостающее поле записи (2.0.0 не знала `check_hash`) `errors.py` дописывает в конец шапки при повторном `fix`. Несовместимо: исправленные ошибки без отпечатка и с пропавшим коммитом теперь отказывают приёмке, пока Судья не вызовет `fix` заново.
- Страж (`delete_guard.py`): `.claude/errors/` закрыт запуску роли (`RPV_ROLE`) так же, как `.claude/decisions.md` и `.claude/goals/` — ни Write/Edit, ни `rm`/`mv`/`>`/`sed -i`/`tee` в оболочке; чтение свободно. Скрипт `errors.py`, запущенный через Bash, пишет в реестр как раньше. Заодно `2>&1` и `2>/dev/null` больше не считаются записью в слово владельца.
- Устав Судьи, `engineer.md`, `researcher.md`, README ролей и вставка хука `role_context.py`: исправленной ошибку объявляет Судья, проверка обязана падать до исправления.

## 1.4.0 — 2026-10-06

### Добавлено

- **`wait_for` v4** — формы `host:<алиас>:<путь | unit:<имя>>` (алиасы `calc`, `vps`, `deck`), `file:<путь>`, `ticket:<ID>`; файл хода `*.json` считается готовым при `done >= total`. Команда `tickets.py wait <ID> <условие> [--on-met ...]` ставит `status: waiting` и условие одной записью. Адреса машин — только из окружения: `RPV_CALC_HOST`, `RPV_VPS_HOST`, `RPV_DECK_HOST` (+ `RPV_DECK_KEY`, `RPV_DECK_KNOWN_HOSTS`); каталог файлов хода — `RPV_PROGRESS_DIR` (по умолчанию `~/rpv/progress`). Не задан хост — условие «не выполнено» и строка в `dispatch.err.log`.
- **Ожидания по событию** (с шиной): `юнит.остановлен/упал`, `задание.готово`, `файл.появился` закрывают `wait_for` сразу; ssh-опрос идёт в отдельном потоке `wait-poller`, тик не блокируется; `RPV_DISPATCH_WAIT_POLL_S`.
- **`on_met` по семантике Судьи**; после таймаута запуска роль продолжает **ту же сессию** (`--session-id`, `RPV_DISPATCH_ON_MET_TIMEOUT_S`).
- **Сторож:** триаж мёртвых целей `wait_for` (хост недоступен, юнита или файла нет) и счётчик застоя.
- **Учёт в токенах:** `cr_tok` / `cw_tok` / `tok_src` в `runs.log`, сводка `usage.py`; запуски без JSON (таймаут) — из транскрипта сессии.
- **Предел параллельности по ролям** — `RPV_DISPATCH_ROLE_PARALLEL=engineer:3`.

### Изменено

- **Шина:** выдача `held → pending` ниже курсора, ack с повтором; сторож машины читает `watch.list` из каталога файлов хода и шлёт `файл.появился`.
- Устав: правило основного дерева и слияния через rebase + проверку + fast-forward.
- Не перенесено (специфика проекта-источника): защита удаления по спискам проекта, автопередача Судье по правилам проекта.
