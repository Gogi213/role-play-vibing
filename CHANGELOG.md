## 1.8.0 — 2026-10-07

### Добавлено

- Хук Stop (`stop_result.py`): запуск роли диспетчера не кончается без записи в лог тикета — иначе Stop блокируется с просьбой сообщить итог (повторный Stop пропускается; `RPV_STOP_STRICT=1` требует запись `[итог: …]` от `tickets.py result`).
- Служба `ci_watch.py` (без ИИ, опрос `gh api` ≤ 60 с, `--repo=<владелец/репо>` или `RPV_CI_REPO`, `--once`): по завершении CI на голове PR пишет запись `ci` в тикет и ставит `next` — красный → владельцу (с именами клеток), зелёный → Судье; форма ожидания `wait_for: ci:<репо>#<PR>`. Привязка PR к тикету — поле `pr:` или `TK-N` в ветке/заголовке.
- Вливание по правилу: `tickets.py accept <ID> --pr N --sha H` (только Судья) пишет `accepted: N@sha`; `merge_rule.py` (работает внутри цикла `ci_watch.py`) вливает PR, когда есть вердикт на текущей голове, CI зелёный на ней и PR сливается; при конфликте — владельцу тикета (раз на голову); цепочка PR ждёт родителя и после его влития переключает базу на `main`.
- `tickets.py result <done|pr|accept|return|blocked|ask-owner|wait>` — итог шага из фиксированного списка с `--why` и доказательством по типу; кого будить, определяет таблица маршрутов `routes.py` (описание — `docs/reliability.md`).
- Страж: замок замеров на машине `RPV_GUARD_HEAVY_HOST` (выключен без переменной) — тяжёлые команды из ssh-сессии вне `systemd-run`/обёртки замера получают отказ с подсказкой `RPV_GUARD_HEAVY_HINT`; классификация — `heavy_guard.py`.
- Ожидание `host:…` без ssh-опроса (с шиной): штатно закрывается событием сторожа машины; ssh — первая проверка и сверка раз в 300 с одним ssh на машину (повторная регистрация пути у сторожа, тревога `recon-miss`), аварийный опрос при шине, лежащей дольше 600 с; журнал `ssh-calls.log`. Файл хода не регистрируется в `watch.list`. Настройка: `RPV_DISPATCH_WAIT_RECON_S`, `RPV_DISPATCH_BUS_DOWN_SSH_S`, `RPV_WATCHED_ALIASES`; без шины — как раньше.
- Сторож: проверки плана шагов на табло — тикет `in_progress` дольше `RPV_WATCH_NO_PLAN_MIN` без плана (`no-plan`) и застывший план при более новой записи роли (`plan-stale`, для `waiting` — напоминание без запуска роли). Роль будится записью в лог тикета с командой `plan.py` плагина и `next: <владелец>`; настройки — `RPV_WATCH_NO_PLAN_MIN`, `RPV_WATCH_PLAN_LAG_MIN`.
- CI: workflow `ci` — тесты на Windows, macOS и Linux × Python 3.11–3.13 на каждый PR и каждый push в `main`, итоговая проверка `ci-ok` (зелёный `ci-ok` — условие слияния по договорённости; защиты ветки нет).
- `/rpv-doctor` — здоровье команды одной таблицей `OK/WARN/FAIL/—`: диспетчер, сторож, присмотр ОС, шина (опрашивается по адресу, с которым живёт диспетчер), очередь, ошибки за сутки, простой. Только читает; код возврата 1 при FAIL, 2 — проект не найден; `--json` — машинный вид.
- Счётчик простоя в диспетчере (`state.json` → `downtime`), SLO `RPV_IDLE_SLO_MIN` (10 мин/сутки), одна тревога в сутки: событие шины `служба.простой.превышен` → CEO (маршрут добавлен в `routes.json`), без шины — строка `idle-slo` в `ceo-inbox.md`, без дубля. Тормоз цикла и пауза по лимиту учитываются отдельно, пауза лимита — вне SLO.
- Прогон на выносливость (`endurance.py`, ночной workflow `endurance.yml`): настоящий диспетчер, фейковые роли и сбои (лимит 429, молчащая роль, `waiting` без условия, жёсткое убийство диспетчера, падение шины и spool, ложное событие юнита, перезагрузка, убийство сторожа и диспетчера под присмотром ОС). Критерий: 0 потерянных сигналов, 0 `blocked`, простой не больше порога.
- Выпуск: `release.py` — `bump` (версия, коммит и тег), `update` (обновить установленный плагин), `rollback` (вернуть прошлую версию одной командой), `check` (версии согласованы; его же проверяет тест в CI).
- Инвариант «у открытого тикета есть ход»: тикет `waiting` или `in_review` без хода дольше `RPV_DISPATCH_INVARIANT_GRACE_S` (600 с) — диспетчер сам будит владельца тикета и пишет строку CEO. Ходом считаются запуск роли, `next`, годный `wait_for`, открытый вопрос владельцу и передача CEO (`--next ceo`); передача CEO без ответа дольше грейса — повторная строка CEO вместо побудки владельца.
- Цикл ожиданий `ticket:<ID>`: `tickets.py wait` отказывает, уже существующий цикл диспетчер сообщает CEO.
- Стандарт сигналов CEO через очередь шины: при заданном `RPV_BUS_URL` сигнал идёт событием `задача.<ID|общее>.к_ceo` в очередь `ceo` с приоритетом (`urgent` / `normal`), CEO читает и подтверждает её командой `tickets.py inbox [--peek]`; запасной путь при лежащей шине — строка с пометкой `[запасной путь]` в `ceo-inbox.md`; будильник — короткая строка в `ceo-wake.log` на каждый сигнал; хук `ceo_signal_guard` запрещает писать эти два файла из сессии. Описание — [docs/signals.md](docs/signals.md).
- `tickets.py` шлёт события шины `задача.<ID>.сдано`, `.статус` и `.вопрос_владельцу`.

### Изменено

- Пауза по лимиту 429 считается от конца запуска, а не от разбора ответа (метка в пределах 2 минут до ответа уже прошла), и не длиннее часа: дальше пробный запуск.
- Шина: после падения слушатель делает короткий запрос — `bus-up` приходит сразу, а не после long-poll на 25 с.
- Откат проверяет тег на GitHub до любых изменений и при сбое возвращает прежний маркетплейс; `update` снимает прибивку к тегу.
- `supervise.env.json` (в `.gitignore`) не содержит секретов: секрет определяется по окончанию имени (`…_TOKEN`, `…_SECRET`, `…_PASSWORD`, `…_API_KEY`); пороги `…_TOKENS` и пути `…_DECK_KEY` / `…_FILE` сохраняются — токен шины давайте файлом `RPV_BUS_TOKEN_FILE`.
- Плашка «КОМАНДА МОЛЧИТ С HH:MM» показывает время в часовом поясе браузера.
- Запись Судьи без `--next` сама возвращает ход владельцу тикета (`researcher` / `engineer`; в `done`, `stopped`, `needs_owner`, `blocked` — нет).
- Диспетчер слушает очередь `ceo` без ack, только ради будильника; порог «не обработано» у очереди `ceo` — 2 часа (у остальных — `--stale-after` шины, 600 с).
- Шаблон устава CEO: при шине строка в `ceo-wake.log` — только повод, сигналы читать `tickets.py inbox`.

### Исправлено

- `merged:<репо>#<PR>`: PR не найден (404) — причина пишется в лог тикета, который ждал этот PR (раньше — только в журнал диспетчера), один раз.
- Сторож: `waiting` с `wait_for` формы `file:`, `host:…:unit:` или недоступным ssh больше не считается сиротой (`watch-orphan-ticket`) — условие проверяет диспетчер.
- Сторож: находки `no-plan`, `plan-stale`, `plan-stale-waiting` не пишутся в `ceo-inbox` — адресат владелец тикета (будится или получает напоминание в логе); автор записей сторожа — `watch`.
- Страж: `-G` у `systemd-run` (`--collect`) не берёт значение — раньше `systemd-run -G rm -rf …` пропускался.
- `save_state` без повторов `replace` ронял тик на Windows.
- cp1252 ронял печать `/rpv-doctor` и `/rpv-start`: stdout/stderr теперь в utf-8.
- Чтение командной строки процесса на Windows повторяется, а не сдаётся на первом сбое.
- Шина: свёртка накопленного в очереди `ceo` («в очереди ceo N событий») — только на первый ответ шины после старта диспетчера.
- Передача CEO: метка пишется на диск раньше очистки `next` — убитый между ними диспетчер не теряет передачу; метка кончается на любом ходе (запуск роли, возврат шапкой, `done`/`stopped`); `next: ceo`, съеденный тиком при живой роли, не делает `waiting` отказом.
- Грейс инварианта считается и от последней записи журнала: комментарий CEO без смены статуса не двигает `updated`, и владелец будился между записью CEO и сменой статуса.
- Подхват роли-сироты после рестарта диспетчера: зеркало запуска пишется до `Popen` (намерение), после — pid и метка старта процесса; живость — по метке старта, а не по имени образа; процесс ищется по `--session-id` (`ps -ww`: на Linux без tty `args` резались по 80 знаков), из совпавших берётся корень дерева; если процесса нет, а вывод роли есть — запуск разбирается как завершённый, а не теряется.

- **Присмотр за диспетчером и сторожем** — `python .claude/dispatcher/supervise.py --install [--project P]`: раз в 5 мин задание ОС (Windows — Планировщик заданий, Linux — `systemd --user` timer, macOS — launchd) проверяет сердцебиение (`state.json` / `watch-heartbeat.json` старше 10 мин или процесса нет) и поднимает службу через `start.py` (WMI / systemd / `Popen`); строки — в `.claude/dispatcher/supervise.log`. Окружение `RPV_*` / `CLAUDE_*` запоминается в `supervise.env.json`. Снять — `--uninstall`.
- **Плашка «КОМАНДА МОЛЧИТ С HH:MM»** (красная) в Диспетчерской, когда сводка команды не приходила > 10 мин, — считает сервер табло, не сторож и не сессия CEO.
- **Диспетчер без простоев:** ответ 429 «session limit · resets …» — не провал запуска, а пауза до сброса, блоки по холостым ходам снимаются сами; сторож при нагрузке сервера ниже порога и ожидании замка заданиями дольше 20 минут будит владельца тикета, державшего замок, иначе — строка CEO.

- `waiting` без `wait_for` и без `next` после запуска владельца → `in_progress`; `todo` → `in_progress` при старте запуска.
- Страж удаления: клон плагина внутри `.claude/worktrees/<имя>` считается рабочей копией.
- Диспетчер и сторож с выводом в файл игнорируют чужой Ctrl+C общей консоли (иначе тихо умирали); службы стартуют под `python.exe`, а не `pythonw.exe`.

## 1.4.0 — 2026-10-06

### Добавлено

- **`wait_for` v4** — формы `host:<алиас>:<путь | unit:<имя>>` (алиасы `calc`, `vps`, `deck`), `file:<путь>`, `ticket:<ID>`; файл хода `*.json` считается готовым при `done >= total`. Команда `tickets.py wait <ID> <условие> [--on-met ...]` ставит `status: waiting` и условие одной записью. Адреса машин — только из окружения: `RPV_CALC_HOST`, `RPV_VPS_HOST`, `RPV_DECK_HOST` (+ `RPV_DECK_KEY`, `RPV_DECK_KNOWN_HOSTS`); каталог файлов хода — `RPV_PROGRESS_DIR` (по умолчанию `~/rpv/progress`). Не задан хост — условие «не выполнено» и строка в `dispatch.err.log`.
- **Ожидания по событию** (с шиной): `юнит.остановлен/упал`, `задание.готово`, `файл.появился` закрывают `wait_for` сразу; ssh-опрос идёт в отдельном потоке `wait-poller`, тик не блокируется; `RPV_DISPATCH_WAIT_POLL_S`.
- **`on_met` по семантике Судьи**; после таймаута запуска роль продолжает **ту же сессию** (`--session-id`, `RPV_DISPATCH_ON_MET_TIMEOUT_S`).
- **Сторож:** триаж мёртвых целей `wait_for` (хост недоступен, юнита или файла нет) и счётчик застоя.
- **Учёт в токенах:** `cr_tok` / `cw_tok` / `tok_src` в `runs.log`, сводка `usage.py`; запуски без JSON (таймаут) — из транскрипта сессии.
- **Предел параллельности по ролям** — `RPV_DISPATCH_ROLE_PARALLEL=engineer:3`.

### Изменено

- **Шина:** выдача `held → pending` ниже курсора, ack с повтором; сторож машины читает `watch.list` из каталога файлов хода и шлёт `файл.появился`.
- Устав: правило основного дерева и слияния через rebase + проверку + fast-forward.
- Не перенесено (специфика проекта-источника): защита удаления по спискам проекта, автопередача Судье по правилам проекта.
