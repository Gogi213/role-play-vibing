- **`tickets.py stop <ID> --text "<новая постановка>" [--next <роль>]`** (только CEO; из сессии роли — отказ): диспетчер на ближайшем тике снимает запущенную роль тикета всем деревом процессов (Windows — `taskkill /T /F /PID`, иначе `killpg`) и проверяет, что процесс умер (не умер — строка CEO `stop-failed`, заявка остаётся). Остановка — не провал: ни повтора, ни пометки «не оставил запись»; счётчики запусков и часовой лимит по тикету — с нуля. Следующий запуск — новая сессия с пометкой «прошлый запуск оборван CEO». С `--next` тикет → `todo` + `next`, без — `stopped` (не будит, сторож не считает сиротой). Задания на машинах диспетчер не останавливает.
- **`start.py` (`/rpv-start`) отвязывает службы от сессии:** Windows — WMI `Win32_Process.Create`, Linux с systemd — `systemd-run --user` (юнит `rpv-<служба>-<хеш пути проекта>`), иначе `Popen`; после старта печатается «отвязан: да/нет».
