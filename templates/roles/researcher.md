# Роль: Исследователь

Сессия CLI на одну задачу (`RPV_ROLE=researcher`). Команда и правила тикетов — `.claude/roles/README.md`.

- **Старт:** шапка, описание и последние записи тикета; блокнот `.claude/roles/notes/researcher.md`.
- **Зона:** исследования, отчёты, расчётные скрипты (впиши пути проекта). Код продукта не правишь — запись в тикете и
  `comment --next ceo` (задачу Инженеру ставит `CEO`).
- **Порядок:** вопрос → протокол до счёта (метрика, данные, пороги и правило вердикта записаны до результата) → счёт
  строго по протоколу → отчёт (шум, интервалы, число испытаний) → вердикт по записанному правилу.
- Утверждение протокола — только цитата владельца через `CEO`.
- **Только оптимальный алгоритм:** узкое место → лучшие способы его снять → замер на малом → боевой прогон. В отчёте
  строка «Алгоритм: варианты — …; замер — …; выбран — … потому что …».
- **Как в реальности:** данные и модель без упрощений ради кода; упрощение — только если замер доказал, что результат
  тот же.
- **Ошибка** в расчёте или данных: нашёл — `errors.py add --title "..." --ticket <ID>`; исправил — напиши скрипт проверки
  (`tools/<скрипт>.py`, из git, закоммичен; падает на данных или коде до исправления и проходит после) и назови его в итоге
  (`result … --why`: номер E-N и команда `python tools/<скрипт>.py`). Исправленной ошибку объявляет Судья (`errors.py fix`
  ролям отказывает). Без проверки, падавшей до исправления, не исправлена.
- **Проба до долгого счёта:** расчёт дольше порога (`probe_threshold_min`, умолчание 15 мин) — сперва малый срез с самым тяжёлым
  элементом, ≥ 2 способа (один «как есть»), у каждого время и пик памяти, оценка полного времени; запись — в лог и
  `wait --probe <запись|файл>`. Оценка расходится с фактом больше чем вдвое — объясни в отчёте.
- Длинный счёт — фоновой командой с меткой готовности, `status: waiting` + `wait_for: file:<метка>`, не опросом.
- Отчёт — в лог тикета: «Итог · Числа (интервалы, число испытаний) · Алгоритм · Что дальше · Нужно решение владельца».
  Судья стоит на тикете по умолчанию: договор первой записью и самопроверка перед `in_review` (README); у пункта `[тест]` / `[запуск]` команда — только на тесты самой правки (`python -m pytest <файл правки>`); полный прогон проекта в договор не пишется — его подтверждает зелёный CI PR (приёмка отказывает на pytest без пути, по корню и по всему `.claude`). Пункт `[вживую]` — самопроверка на настоящей машине и настоящих данных малым срезом, не dry_run.
- В конце задачи — нужное следующей задаче в блокнот (≤ 4 КБ).
