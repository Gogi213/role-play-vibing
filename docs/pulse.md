# Пульс: `pulse.json` (TK-095, В-38)

Раз в тик диспетчер пишет `.claude/dispatcher/pulse.json` — один файл на проект, только текущие сутки (локальное время проекта), размер от истории не растёт. Читает его табло (шаг 2) и закреплённое сообщение Telegram. Макет: `docs/findings/pulse-mockup-2026-11-02.html`. Код — `.claude/dispatcher/pulse.py`.

## Поля
| поле | что |
|---|---|
| `version`, `project`, `day`, `generated` | служебные; `generated` — время записи файла (читатель: старше 10 мин — срок смотрителя, `heartbeat.STALE_S` — диспетчер молчит, см. `pulse.read`; тик бывает долгим) |
| `state` | `ok` · `owner` · `stuck` |
| `phrase` | «Всё идёт. От вас ничего.» / «Нужны вы: <проект> — <действие> по TK-N.» / «Застряло: <проект> — <причина>.» (при двух состояниях «Застряло» первее) |
| `now` | «<роль> · TK-N» активного запуска; «запусков нет, в очереди N»; «очередь пуста» |
| `pause` | самая длинная череда клеток без запусков до текущей: «чч:мм–чч:мм · минут · причина»; короче 30 мин или нет — пусто |
| `reasons` | `[{code, detail, since}]` — причины «застряло», что держатся дольше порога |
| `owner` | `[{ticket, action}]` — что ждёт слова владельца |
| `cells` | 96 клеток по 15 минут: `{i, n, c, why?}` — номер, число завершённых запусков ролей (`runs.log`, `on_met` не в счёт), класс, код причины для `stuck` |
| `goal`, `job`, `ask`, `fix` | версия 2 (TK-105, `pulse_facts.py`): `goal` `{id,title,step?,steps?}` — открытая цель владельца активного тикета, шаг — по строке «Шаг N из M цели G-NNN.»; `job` `{role,who,verb,ticket,title,since}` — самый давний идущий запуск; `ask` `{ticket,question,since?}` — вопрос владельцу; `fix` `{text,who}` — причина «застряло» по-человечески и кто чинит. Нет источника — поля нет |
| `plan` | версия 2 (TK-108, В-53): план текущей цели по шагам `[{mark, n, title, ticket?, who?, at?, idle?, level?, waiting?}]`. `mark`: `done` ✓ принят (`at` — время приёмки: «19:03» · «вчера» · «07.11»), `run` ◐ идёт (`who` — роль по-русски), `ask` ? ждёт слова владельца (`waiting` — сколько), `stuck` ! застряло (причина называет тикет или все тикеты шага остановлены), `next` ○ впереди. `idle` — сколько без движения: позже из последней записи лога тикета, последнего запуска роли (`runs.log`) и начала идущего запуска; `level` — `""` · `warn` (от `pulse_move_warn_min` = 15 мин) · `bad` (от `pulse_move_bad_min` = 30 мин). Шаги — `goal --step` (`registry.goal_steps`), тикет шага — по строке «Шаг N из M цели G-NNN.»; у цели нет плана — открытые тикеты цели тем же списком (`n` = 0, до 12). «Шаг N из M» и полоска цели — из этого же списка (N — первый непринятый шаг, все приняты — последний). Нет цели или плана — поля нет |
| `status` | версия 2 (TK-117, В-57): блок «Статус» раскрытой карточки `{rows, more, left, hold}`. `rows` — тикеты текущей цели (нет цели — открытые тикеты проекта, до 12) `[{ticket, title, mark, where, level?}]`: `title` — заголовок до 40 знаков без «Хвост TK-N:», `mark` (`done` · `run` · `ask` · `stuck` · `next`) — как у `plan`, `where` — «Где сейчас» кодом: «принят чч:мм» · «Инженер делает» · «Инженер правит после возврата» · «у Судьи» · «в очереди» · «ждёт TK-N» (у тикета в очереди — предыдущий не принятый шаг плана по номеру `n`; у ожидающего — из `wait_for`, там же «ждёт слияния» · «ждёт CI» · «ждёт результата») · «ждёт CEO» (`blocked`) · «ждёт вашего ответа» · «стоит N мин»; `level` — `warn` (от `pulse_move_warn_min`) · `bad` (от `pulse_move_bad_min`; у названного причиной «застряло» всегда). Принятых показано последние 3, остальные — число в `more`. `left` — «Осталось»: непринятые шаги плана (до 4, коротко, «и ещё N»), плана нет — номера открытых тикетов. `hold` — «Держит»: одна причина — вопрос владельцу › застряло › самый долгий без движения (от порога жёлтого); пусто — «Держит» не показывается. Нет тикетов и «Осталось» — поля нет |
| `done_today`, `queue`, `day` | версия 2: принятое Судьёй сегодня `[{time,ticket,title}]`, открытые тикеты без идущего запуска `[{ticket,title}]` (до 12), итоги `{accepted,returns,working,queued}` |

## Класс клетки
Считается на момент клетки: каждый тик записывает в `state.json` (`pulse_cells`) состояние текущей клетки, худшее за неё; задним числом по тикетам не пересчитывается. Порядок: `work` (есть запуски или шёл запуск) › `stuck` › `owner` › `none`.
- `work` — запуски есть; `none` — запусков нет и ни одной причины «застряло» нет, слова владельца не ждут: пусто в очереди, ожидание задания на машине, а также открытые тикеты (`todo`/`blocked`/`in_review`…) в пределах порога — «очередь есть, причины нет» не `stuck`;
- `owner` — только `needs_owner` и `waiting` с условием «слово владельца» / «ответ владельца» в `wait_for`; «owner» в пути или имени репозитория не в счёт. Другой класс жёлтым не считается;
- `stuck` — запусков нет, а причина из списка есть. Клетки, пропущенные при молчавшем диспетчере, — `stuck`/`dispatcher_dead`.

## Коды причин и пороги (умолчания; ключи — `.claude/rpv.json`, `docs/configuration.md`, менять — Судья)
| код | когда | порог |
|---|---|---|
| `dispatcher_dead` | тишина с конца прошлого тика (`state.last_tick_end`; долгий тик — не тишина) | `pulse_dead_min` = 2 мин |
| `unserved` | тикет в очереди, слот свободен, запуска нет; подпричина из `dt_flags`: `limit_paused` (лимит сессии), `throttled`, `ready_unserved` | `pulse_unserved_min` = 20 мин |
| `step_uncovered` | принятый шаг открытой цели или тикет с `--tail ceo:` без следующего тикета — тот же расчёт, что у сигнала `watch-goal-idle` (TK-086) | `goal_idle_min` = 10 мин |
| `loop` | у открытого тикета ≥ `pulse_loop_returns` возвратов Судьи, или ≥ `pulse_loop_errors` запусков не `ok` за `pulse_loop_window_min` | 2 · 2 · 60 мин |
| `merged_unreleased` | сторож держит находку `unreleased:<ветка>` (TK-062); любая ветка репозитория; нужен `ci_repo` (`watch_unreleased: false` выключает) | без своего порога |
| `ci_red` | у открытого тикета с `pr:` (список `149, 153` — каждый номер) CI красный (`ci-state.json`) или конфликт с веткой по умолчанию (в тексте — её имя из `merge-state.json` `base`): `conflict` равен текущей голове PR (`ci-state` `sha`); закрытые и влитые PR (`closed: true` в `ci-state.json`, ставит ci_watch) пропускаются; нужен `ci_repo` | `pulse_ci_red_min` = 30 мин |

Причину «ждёт Судья/Инженер» без одного из кодов Пульс не выдумывает: нет кода — клетка не `stuck`.

## Шаг 2 — страница и закреплённое сообщение Telegram (TK-096)

Читают `pulse.json` каждого проекта в том виде, в каком его пишет шаг 1 (таблица полей выше; код чтения — `.claude/dispatcher/pulse_view.py`).
Из полей берутся `state`, `now`, `cells[].c` / `cells[].n` / `cells[].runs`, `generated` и поля версии 2 (`goal`, `job`, `ask`, `fix`, `done_today`, `queue`, `day`); `phrase` и `pause` — только запасом для версии 1, `reasons` страница не показывает.
- `generated` старше 10 минут (`heartbeat.STALE_S`, тот же порог, что у `pulse.read`; `pulse_dead_min` — другое: он решает, пишет ли диспетчер клетки `dispatcher_dead`) —
  страница сама пишет «Застряло: <имя> — диспетчер не отвечает N мин.», клетки после последней записи красные, прежние «сейчас» и пауза не показываются.
- Сутки и номер клетки считаются по поясу `generated` (поясу проекта), а не сервера страницы; часы в шапке — тоже по поясу проекта.
- Файл не читается, `state` не из списка, `cells` не список, `generated` не время — «Застряло: <имя> — пульс не читается.». Список проектов пуст
  или `rpv.json` не читается — «Проектов нет: …» красным, не «Всё идёт». Машин, процессов, тикетов на верхнем уровне, истории дальше суток нет.

### Страница

Один файл `.claude/board/pulse_server.py` (stdlib `http.server`) и шаблон `.claude/board/pulse.html`.

```
PULSE_TOKEN=<длинный-ключ> python <плагин>/.claude/board/pulse_server.py --project <проект> --host 127.0.0.1 --port 8787
```

- Слушает только `127.0.0.1`, наружу — через обратный прокси с TLS (nginx/caddy): ключ лежит в пути, по голому HTTP он виден всем на дороге.
  `--host 0.0.0.0` без TLS-прокси не использовать.
- Адрес за прокси `https://<домен>/<ключ>/` (напрямую на машине — `http://127.0.0.1:8787/<ключ>/`); другой путь — 404. `/<ключ>/body` — только содержимое (его берёт автообновление раз в 30 с:
  подменяется, лишь если изменилось, мерцания нет; не вышло обновить — под рамкой красная строка «Не удалось обновить · чч:мм»). Ключ без
  `--token`/`PULSE_TOKEN` — сервер не стартует.
- Проекты — ключ `pulse_projects` в `<проект>/.claude/rpv.json`: `{"rpv": "C:/proj/rpv/.claude/dispatcher/pulse.json",
  "invoice": "https://host.example/invoice/pulse.json"}`. Путь — файл на этой машине, `http(s)://` — простой GET (5 с).
- Страница по макету docs/pulse-mockup-v2.html (до 1040 px шириной). Шапка: «Всё идёт / От вас ничего не нужно» · «Нужен ваш ответ / <проект> · TK-N: <вопрос>» ·
  «Застряло: <проект> / <причина> — <кто чинит>»; про остальные проекты — число в переключателе **Все | Идёт | Нужен ответ | Застряло** (выбор помнится в `localStorage`).
  Ниже — итоги дня по всем проектам (принято сегодня, возвраты, в работе, в очереди) и карточка проекта: цель владельца и «шаг N из M» с полоской (только если у цели есть план; числа — из списка плана),
  клетки (8 часов, 32 клетки, правый край — текущая; уже 760 px — 4 часа), часы ровно над своими клетками, справа «<Роль> делает/проверяет <заголовок>» и «TK-N · длительность»;
  у «нужен ответ» — вопрос и кнопка «Ответить» (только если у `ask` есть `link` с http(s)), у «застряло» — причина и кто чинит. В свёрнутой карточке плана нет: слева цель, «шаг N из M» и полоска, справа строка «что сейчас» с меткой-таймером перед ней — «N мин назад» (серая, есть движение), «стоит N мин» (жёлтая от 15, красная от 30), «ждёт N мин» (ответ владельца); строка не повторяет число метки. В раскрытой карточке первым блоком «Статус»: таблица Задача | Что | Где сейчас по тикетам цели (принятые серым, больше трёх — строка «принято ещё N»; «ждёт вашего ответа» жёлтое, «стоит N мин» жёлтое от 15 и красное от 30), под ней одна строка «Осталось: … · Держит: …». Файл устарел (диспетчер молчит) — «Где сейчас» у непринятых, «Держит» и метка-таймер не показываются. Нажатие на карточку — «Статус», «Сделано сегодня» и «Дальше по очереди».
- Клетки: наведение (на телефоне касание) подсвечивает клетку и столбец того же времени у всех проектов, остальные приглушены; подсказка — «<проект> · чч:мм–чч:мм» (текущая — «· сейчас»),
  метка статуса (Тихо / N запусков / Ждали ответа / Застряло) и до трёх строк «Роль · заголовок (TK-N)», «и ещё N». Карточки без полей версии 2 (pulse.json версии 1) показываются без цели, итогов и списков.
  Тёмная тема — по `prefers-color-scheme`.
- Юнит systemd (вместо старого табло на VPS):

```ini
[Unit]
Description=Пульс (rpv)
After=network-online.target

[Service]
EnvironmentFile=/etc/rpv/pulse.env
ExecStart=/usr/bin/python3 /opt/rpv/.claude/board/pulse_server.py --project /srv/hub --host 127.0.0.1 --port 8787
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

Ключ — в `/etc/rpv/pulse.env` (`PULSE_TOKEN=<длинный-ключ>`, права 0600, владелец root): в `Environment=` он виден всем через
`systemctl show`.

Замена старого табло: `systemctl disable --now rpv-board`, положить юнит в `/etc/systemd/system/rpv-pulse.service`,
`systemctl enable --now rpv-pulse`; снаружи — прежний обратный прокси (с TLS) на порт 8787.

### Закреплённое сообщение в Telegram

В rpv.json проекта-ведущего: `"pulse_telegram": true` и `pulse_projects` (тот же список). Диспетчер ведущего:

- первая строка — фраза-итог (застряло важнее «нужны вы»), дальше по строке на проект: «имя — идёт» / «имя — нужны вы: …» /
  «имя — застряло: …»;
- сообщения нет — создаёт и закрепляет, `message_id` — в `state.json` (`pulse_tg`); дальше только `editMessageText`; закрепить не вышло
  (нет прав) — повтор раз в минуту, всего 3 попытки;
- правка — только при смене текста и не чаще раза в минуту; удалили сообщение — создастся новое и закрепится заново;
- «отправлено» в `notify.log` — только при ответе API `ok`.

Нужны `RPV_TG_TOKEN` и `RPV_TG_CHAT` ([configuration.md](configuration.md)). Каждый проект на этой машине пишет pulse.json в свой
`.claude/dispatcher/`; удалённый отдаёт его по URL.

## Пульс на сервере: страница на Софии, проекты присылают файл сами (TK-113, В-56)

Страница одна на все машины (ПК, мак): проект сам отправляет свой `pulse.json`, ssh-ключ на клиенте не нужен. Код отправки — `.claude/dispatcher/pulse_push.py`
(вызывается в тике диспетчера после записи `pulse.json`), приём — `pulse_server.py --inbox`.

| что | значение |
|---|---|
| страница (владельцу, телефон и ПК) | `https://13.140.29.171:9447/<ключ чтения>/` |
| приём | `PUT https://13.140.29.171:9447/put/<имя проекта>`, заголовок `Authorization: Bearer <ключ записи>`; тело — `pulse.json` как есть (до 512 КБ) |
| ключи | два разных: чтение (в пути страницы) и запись (в заголовке); хранятся только в `/etc/rpv/pulse.env` на Софии (0600, root: `PULSE_TOKEN`, `PULSE_WRITE_TOKEN`) и в тикете TK-113; в git их нет |
| сервер | ssh-хост `vps`: юнит `rpv-pulse` (systemd, автозапуск, `DynamicUser`, порт 127.0.0.1:8791, данные `/var/lib/rpv-pulse/inbox/<имя>.json`), код в `/opt/rpv/.claude/{board,dispatcher}` (5 файлов: `board/pulse_server.py`, `board/pulse.html`, `dispatcher/{pulse_view,heartbeat,project}.py`) |
| снаружи | один файл nginx `/etc/nginx/sites-enabled/rpv-pulse`: порт 9447, TLS тем же сертификатом Let's Encrypt на IP, что у соседей; `access_log off` (ключ чтения лежит в пути, в журнале ему не место) |

**Подключить проект** (одна команда в сессии CEO проекта, после обновления плагина до версии с `pulse_push`; ключ записи — из тикета TK-113 или `ssh vps cat /etc/rpv/pulse.env`):

```
python <плагин>/.claude/dispatcher/tickets.py --project <проект> config set pulse_push '{"url":"https://13.140.29.171:9447","name":"<имя>","key":"<ключ записи>"}' --why "страница Пульса на сервере" --ref В-56
```

Имя — латиница, цифры, `_`, `-`, до 40 знаков (`rpv`, `invoice`). Запись ключа в rpv.json лежит рядом с проектом: файл не публиковать (в rpv он в `.git/info/exclude`).
Разовая отправка без диспетчера: `python <плагин>/.claude/dispatcher/pulse_push.py --project <проект>` (код 0 — принято).

**Как читается.** Присланные файлы — проекты страницы наравне с `pulse_projects`: сначала проекты из rpv.json сервера (если он есть), затем присланные по алфавиту.
Отправка — после каждого тика, не чаще раза в минуту, таймаут 4 с; сбой тик не валит, в `notify.log` одна строка на смену причины («пульс на сервер: не отправлено (…)», «снова отправляется»).
Файл старше 10 минут (порог тот же) показывается как «Застряло: <имя> — нет данных N мин», клетки после последней записи красные, прежние «сейчас» и цифры не показываются;
у страницы на машине проекта текст прежний («диспетчер не отвечает»). Диспетчер выключен — присланного не прибавляется, на странице будет «нет данных»: проект, который выключен совсем, можно убрать с неё, удалив `/var/lib/rpv-pulse/inbox/<имя>.json`.
alpha (диспетчер выключен, В-43): его последний `pulse.json` отправлен на сервер один раз разовой отправкой — на странице он стоит как «Застряло: alpha — нет данных N дней», и это честное состояние, а не сбой; живым alpha станет, когда в нём снова заработает диспетчер с `pulse_push`.

**Безопасность, честно.** Страница и приём — только по ключам; снаружи только TLS (сертификат на IP от Let's Encrypt, домена нет; срок сертификата короткий, его продлевает сервер для соседних сервисов, не этот проект).
Ключ записи уходит в заголовке (в журналы nginx не попадает: `access_log off`), ключ чтения виден в адресе страницы тому, кто видит ваш экран и историю браузера; сменить — правка `/etc/rpv/pulse.env` и `systemctl restart rpv-pulse`.
Голый `http://` отправка принимает только для localhost. **Известный риск:** порт 9447 отвечает и на голый http (nginx — 400, страницу не отдаёт), но запрос с ключом чтения в пути уже ушёл открытым текстом — адрес набирать только с `https://`, закладку держать с `https://`. Один ключ записи на все проекты: кто его знает, может перезаписать состояние любого проекта на странице (деньги и код он не открывает).
На сервере общий диск с alpha (сторож места режет при свободном < 23 ГБ): весь проект занимает меньше 1 МБ.
