# Пульс: `pulse.json` (TK-095, В-38)

Раз в тик диспетчер пишет `.claude/dispatcher/pulse.json` — один файл на проект, только текущие сутки (локальное время проекта), размер от истории не растёт. Читает его табло (шаг 2) и закреплённое сообщение Telegram. Макет: `docs/findings/pulse-mockup-2026-11-02.html`. Код — `.claude/dispatcher/pulse.py`.

## Поля
| поле | что |
|---|---|
| `version`, `project`, `day`, `generated` | служебные; `generated` — время записи файла (читатель: старше 10 мин — срок смотрителя, `heartbeat.STALE_S` — диспетчер молчит, см. `pulse.read`; тик бывает долгим) |
| `state` | `ok` · `owner` · `stuck` |
| `phrase` | «Всё идёт. От вас ничего.» / «Нужны вы: <проект> — <действие> по TK-N.» / «Застряло: <проект> — <причина>.» (при двух состояниях «Застряло» первее) |
| `now` | «<роль> · TK-N» активного запуска; «запусков нет, в очереди N»; «очередь пуста» |
| `pause` | самая длинная череда клеток без запусков до текущей: «чч:мм–чч:мм · минут · причина»; короче 30 мин или нет — пусто |
| `reasons` | `[{code, detail, since}]` — причины «застряло», что держатся дольше порога |
| `owner` | `[{ticket, action}]` — что ждёт слова владельца |
| `cells` | 96 клеток по 15 минут: `{i, n, c, why?}` — номер, число завершённых запусков ролей (`runs.log`, `on_met` не в счёт), класс, код причины для `stuck` |

## Класс клетки
Считается на момент клетки: каждый тик записывает в `state.json` (`pulse_cells`) состояние текущей клетки, худшее за неё; задним числом по тикетам не пересчитывается. Порядок: `work` (есть запуски или шёл запуск) › `stuck` › `owner` › `none`.
- `work` — запуски есть; `none` — запусков нет и ни одной причины «застряло» нет, слова владельца не ждут: пусто в очереди, ожидание задания на машине, а также открытые тикеты (`todo`/`blocked`/`in_review`…) в пределах порога — «очередь есть, причины нет» не `stuck`;
- `owner` — только `needs_owner` и `waiting` с условием «слово владельца» / «ответ владельца» в `wait_for`; «owner» в пути или имени репозитория не в счёт. Другой класс жёлтым не считается;
- `stuck` — запусков нет, а причина из списка есть. Клетки, пропущенные при молчавшем диспетчере, — `stuck`/`dispatcher_dead`.

## Коды причин и пороги (умолчания; ключи — `.claude/rpv.json`, `docs/configuration.md`, менять — Судья)
| код | когда | порог |
|---|---|---|
| `dispatcher_dead` | тишина с конца прошлого тика (`state.last_tick_end`; долгий тик — не тишина) | `pulse_dead_min` = 2 мин |
| `unserved` | тикет в очереди, слот свободен, запуска нет; подпричина из `dt_flags`: `limit_paused` (лимит сессии), `throttled`, `ready_unserved` | `pulse_unserved_min` = 20 мин |
| `step_uncovered` | принятый шаг открытой цели или тикет с `--tail ceo:` без следующего тикета — тот же расчёт, что у сигнала `watch-goal-idle` (TK-086) | `goal_idle_min` = 10 мин |
| `loop` | у открытого тикета ≥ `pulse_loop_returns` возвратов Судьи, или ≥ `pulse_loop_errors` запусков не `ok` за `pulse_loop_window_min` | 2 · 2 · 60 мин |
| `merged_unreleased` | сторож держит находку `unreleased:<ветка>` (TK-062); любая ветка репозитория; нужны `watch_unreleased: true` и `ci_repo` | без своего порога |
| `ci_red` | у открытого тикета с `pr:` (список `149, 153` — каждый номер) CI красный (`ci-state.json`) или конфликт с веткой по умолчанию (в тексте — её имя из `merge-state.json` `base`): `conflict` равен текущей голове PR (`ci-state` `sha`); закрытые и влитые PR (`closed: true` в `ci-state.json`, ставит ci_watch) пропускаются; нужен `ci_repo` | `pulse_ci_red_min` = 30 мин |

Причину «ждёт Судья/Инженер» без одного из кодов Пульс не выдумывает: нет кода — клетка не `stuck`.

## Шаг 2 — страница и закреплённое сообщение Telegram (TK-096)

Читают `pulse.json` каждого проекта в том виде, в каком его пишет шаг 1 (таблица полей выше; код чтения — `.claude/dispatcher/pulse_view.py`).
Из полей берутся `state`, `phrase`, `now`, `pause`, `cells[].c` / `cells[].n`, `generated`; остальное (`reasons`, `owner`) страница не показывает.
- `generated` старше 10 минут (`heartbeat.STALE_S`, тот же порог, что у `pulse.read`; `pulse_dead_min` — другое: он решает, пишет ли диспетчер клетки `dispatcher_dead`) —
  страница сама пишет «Застряло: <имя> — диспетчер не отвечает N мин.», клетки после последней записи красные, прежние «сейчас» и пауза не показываются.
- Сутки и номер клетки считаются по поясу `generated` (поясу проекта), а не сервера страницы; часы в шапке — тоже по поясу проекта.
- Файл не читается, `state` не из списка, `cells` не список, `generated` не время — «Застряло: <имя> — пульс не читается.». Список проектов пуст
  или `rpv.json` не читается — «Проектов нет: …» красным, не «Всё идёт». Машин, процессов, тикетов на верхнем уровне, истории дальше суток нет.

### Страница

Один файл `.claude/board/pulse_server.py` (stdlib `http.server`) и шаблон `.claude/board/pulse.html`.

```
PULSE_TOKEN=<длинный-ключ> python <плагин>/.claude/board/pulse_server.py --project <проект> --host 127.0.0.1 --port 8787
```

- Слушает только `127.0.0.1`, наружу — через обратный прокси с TLS (nginx/caddy): ключ лежит в пути, по голому HTTP он виден всем на дороге.
  `--host 0.0.0.0` без TLS-прокси не использовать.
- Адрес за прокси `https://<домен>/<ключ>/` (напрямую на машине — `http://127.0.0.1:8787/<ключ>/`); другой путь — 404. `/<ключ>/body` — только содержимое (его берёт автообновление раз в 30 с:
  подменяется, лишь если изменилось, мерцания нет; не вышло обновить — под рамкой красная строка «Не удалось обновить · чч:мм»). Ключ без
  `--token`/`PULSE_TOKEN` — сервер не стартует.
- Проекты — ключ `pulse_projects` в `<проект>/.claude/rpv.json`: `{"rpv": "C:/proj/rpv/.claude/dispatcher/pulse.json",
  "invoice": "https://host.example/invoice/pulse.json"}`. Путь — файл на этой машине, `http(s)://` — простой GET (5 с).
- Широкий экран: последние 8 часов (32 клетки), правый край — текущая клетка. Уже 480 px: сутки по 2 часа в клетке (12 клеток).
  Тёмная тема — по `prefers-color-scheme`.
- Юнит systemd (вместо старого табло на VPS):

```ini
[Unit]
Description=Пульс (rpv)
After=network-online.target

[Service]
EnvironmentFile=/etc/rpv/pulse.env
ExecStart=/usr/bin/python3 /opt/rpv/.claude/board/pulse_server.py --project /srv/hub --host 127.0.0.1 --port 8787
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

Ключ — в `/etc/rpv/pulse.env` (`PULSE_TOKEN=<длинный-ключ>`, права 0600, владелец root): в `Environment=` он виден всем через
`systemctl show`.

Замена старого табло: `systemctl disable --now rpv-board`, положить юнит в `/etc/systemd/system/rpv-pulse.service`,
`systemctl enable --now rpv-pulse`; снаружи — прежний обратный прокси (с TLS) на порт 8787.

### Закреплённое сообщение в Telegram

В rpv.json проекта-ведущего: `"pulse_telegram": true` и `pulse_projects` (тот же список). Диспетчер ведущего:

- первая строка — фраза-итог (застряло важнее «нужны вы»), дальше по строке на проект: «имя — идёт» / «имя — нужны вы: …» /
  «имя — застряло: …»;
- сообщения нет — создаёт и закрепляет, `message_id` — в `state.json` (`pulse_tg`); дальше только `editMessageText`; закрепить не вышло
  (нет прав) — повтор раз в минуту, всего 3 попытки;
- правка — только при смене текста и не чаще раза в минуту; удалили сообщение — создастся новое и закрепится заново;
- «отправлено» в `notify.log` — только при ответе API `ok`.

Нужны `RPV_TG_TOKEN` и `RPV_TG_CHAT` ([configuration.md](configuration.md)). Каждый проект на этой машине пишет pulse.json в свой
`.claude/dispatcher/`; удалённый отдаёт его по URL.
