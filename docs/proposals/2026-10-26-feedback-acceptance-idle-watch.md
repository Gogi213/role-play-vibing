# Обратная связь 2.0.6 (проект alpha, 23–26.10.2026, тикеты TK-364…TK-410)

Источник: живой прогон команды CEO + Исследователь + Инженер + Судья (диспетчер, сторож, надзиратель) за трое суток исследования.
Числа — из логов тикетов и `ceo-wake.log` проекта.

## 1. Приёмка: много возвратов
- `accept` 45, `return` 127 — около 3 возвратов на одну приёмку. Лидеры: один тикет 17 возвратов, два — по 10.
- Часть возвратов — реальные дефекты метода, пойманные Судьёй (заглядывание в будущее, неверный тариф, агрегаты вместо событий,
  устаревшая котировка). Это работает как задумано.
- Часть — исследователь сдаёт `done`, хотя в собственном отчёте пишет «не сделано»; один и тот же пункт возвращался 3 раза подряд.
- **Предложение:** проверка перед `done` у исполнителя — если в итоге/отчёте есть «не сделано», `done` не принимается
  (`blocked` с причиной либо строка «нет и почему» с командой проверки). Чек-лист пунктов последнего возврата — в подсказке сдачи.

## 2. ask-owner не по адресу
- `ask-owner` 16 раз; большинство — методические развилки (какой порог, какой контроль, оставлять ли окна), которые по уставу решает
  Судья/CEO, а не владелец.
- **Предложение:** `ask-owner` требует `--why-owner` из короткого списка (деньги, доступы/ключи, регистрация, направление цели);
  иначе автоматически `--next judge`.

## 3. Простои вычислителя
- Типовые причины: роль ждёт закачку и не считает готовое; хвост одной позиции держит всю заявку ядер; закачка подана как вычислительная
  заявка; сборка по позициям одним процессом.
- Две причины закрыты в планировщике проекта (отдельный класс сетевых заданий вне суммы ядер; отдача ядер из хвоста).
- **Предложение (плагин):** в подсказке роли при `wait` — строка «загрузка вычислителя сейчас N; что можно считать на готовом?»;
  сторож — сигнал «вычислитель простаивает ≥ 15 мин при открытых тикетах в wait».

## 4. Сторож: много ложных тревог
- За трое суток: `blocked` 20, `watch-blocked` 10, `watch-orphan-ticket` 8, «хвост» 9 — заметная доля ложных.
- Причины: задания, запущенные мимо планировщика (юниты без префикса), не видны; `wait_for` на старое имя юнита после перезапуска;
  слово «хвост» в тексте записи распознаётся как итог «хвост» (а это имя механизма); несколько раз «диспетчер не разбудил за 15 мин».
- **Предложение:** итог «хвост» распознавать только по явному полю (`хвост CEO:`), не по слову; `wait_for` на юнит — по шаблону/метке,
  переживающей перезапуск; явное предупреждение роли, если её юнит запущен мимо планировщика.

## 5. Сбои
- Сетевой обрыв API у роли (ECONNRESET, 0 токенов) дважды подряд → тикет ушёл в `blocked` как «холостой ход». Нужно отличать
  сетевую ошибку (повтор) от холостого хода.
- OOM всего хоста от задания роли мимо планировщика (без лимита памяти).
- Оценки сроков ролей регулярно мимо (по числу файлов вместо объёма) — в подсказке `wait` просить основание оценки.
