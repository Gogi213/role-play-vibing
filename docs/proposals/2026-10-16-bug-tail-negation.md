# Багрепорт 2.0.6: `--tail -` отклоняется, когда исполнитель пишет «Хвостов нет»

**Что случилось (alpha, TK-264, 16.10 ~09:00).** Исполнитель сдал работу с итогом, который кончался словами «… Хвостов нет».
Судья принимал с `--tail -` (хвостов нет). Проверка сверила `-` с последней сдачей исполнителя, нашла там слово «хвост» и
отказала. Судье пришлось уходить через `--tail ceo:"…"` и писать CEO пустой хвост; CEO получил лишний сигнал `хвост`.

**Причина.** `.claude/dispatcher/tickets.py:304–305`, `TAIL_WORDS`:

```
не\s+сделан|…|не\s+работает|\bхвост|\bосталось\b|отдельн\w*\s+тикет
```

`\bхвост` ловит любое слово с этим корнем, в том числе отрицание «хвостов нет», «хвоста нет», «без хвостов», то есть ровно ту
фразу, которой исполнитель сообщает, что хвостов нет. Поиск — `tickets.py:364` (`TAIL_WORDS.search(sub)`).

**Предложение.** Перед поиском убирать из текста отрицания: `хвост\w*\s+нет`, `нет\s+хвост\w*`, `без\s+хвост\w*` (и `осталось 0`,
`ничего не осталось`). Или отдельная регулярка-исключение, которая гасит совпадение `\bхвост` в этих оборотах.

**Тест.**
- «… Хвостов нет» + `--tail -` → приёмка проходит;
- «хвоста нет, всё сделано» + `--tail -` → проходит;
- «хвост: нет метрик у 431 строки» + `--tail -` → отказ (как сейчас);
- «не сделано: регистрация в settings.json» + `--tail -` → отказ (как сейчас).
