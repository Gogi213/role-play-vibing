# Обратная связь 2.0.9 (invoice): обновление с 2.0.5 — что сломалось и что закрыть в плагине

Проект invoice, 27.10.2026, 17:10–17:40; отправка — В-138 («отправь все что мы нашли в качество пулреквеста в реп плагина»). Обновление с 2.0.5 до 2.0.9 по слову владельца (В-137: «нужно полностью
обновиться. на новую версию»). После него владелец попросил критика проверить всё, что CEO сделал с момента обновления.
Критик нашёл семь ошибок. Четыре из них плагин мог бы не дать сделать, они ниже как П1–П4. Ещё три закрыты в проекте,
это раздел «Сделано у себя». Каждое утверждение проверено выводом команды или файлом; где не проверено, так и написано.

## Что произошло

1. `claude plugin update` → «updated from 2.0.5 to 2.0.9 … Restart to apply changes». Дальше `start.py` и `supervise.py
   --install` из 2.0.9, `doctor.py`.
2. Claude Code не перезапущен. Сессия CEO доработала до конца на хуках 2.0.5. В страже 2.0.5 нет ни запрета записи
   `.claude/roles/*.md` (2.0.7/2.0.9), ни журнала `config set`, то есть запреты, написанные под CEO, на CEO не действовали.
   Каталог 2.0.5 при этом помечен `.orphaned_at`. Если его уберут раньше перезапуска, хуки сессии смотрят в пустоту.
3. `supervise.py --install` переписал plist присмотра без `EnvironmentVariables`. Это та же ловушка, что 13.10, 16.10 и
   27.10: диспетчер, поднятый launchd, не находит `claude`. PATH и `CLAUDE_BIN` дописаны руками.
4. В `doctor` была строка `FAIL простой сегодня 26 мин из 10 (… тормоз запусков 26)`. CEO назвал вывод «зелёным».
5. `charter sync` положил шаблоны 2.0.9 как есть и стёр проектные строки уставов: у Судьи 5 строк (`presubmit`, `check_all`
   при сдаче макета), у инженера 8, у исследователя 2, в README 6. Синк запущен до записи В-137 и без `--ref`, поэтому в
   `charter-log.json` поля ref и quote пустые.
6. CEO перенёс стёртые строки в `CLAUDE.md` сам, без плана и без тикета Судье. Две строки при этом потерял, критик их
   нашёл, CEO дописал. Коммит CEO `a4d6a128` ушёл в `origin/main` вместе с пушем принятого Судьёй TK-401, то есть без
   приёмки. Позже проверку переноса провёл Судья (TK-403): все 13 проектных строк на месте, ни одной потерянной.

## Предложения в плагин

### П1. Синк уставов не стирает проектные строки

**Сейчас.** `tickets.py charter sync` переносит `templates/roles/*.md` как есть. Проектными остаются только строки таблицы
зон в README. Правила проекта для ролей (с чего Судья начинает приёмку, что обязательно в сдаче) жить в уставе не
могут: следующий синк их сотрёт, а руками писать уставы страж CEO не даёт. Мы вынесли их в `CLAUDE.md`. Это работает,
но правила Судьи теперь лежат в общем файле проекта, а не у Судьи.

**Предложение.** Файл добавок `.claude/roles/project/<роль>.md`: его синк не трогает, а диспетчер подклеивает к уставу
роли при запуске (или синк дописывает его в конец устава отдельным блоком). Писать его — только CEO через ту же команду
с `--ref В-N`, с записью в `charter-log.json`.

**Проверка.** Тест: в проекте устав плюс файл добавок, `charter sync` на новом шаблоне, и строка добавки есть в том, что
получает роль при запуске.

### П2. Сессия на старой версии плагина — первой строкой

**Сейчас.** После `plugin update` README плагина говорит «restart Claude Code», CLI тоже пишет «Restart to apply». Но
в уже открытой сессии об этом ничего не напоминает, и CEO работает на старом страже без новых запретов. Диспетчер и
сторож при этом уже новые, поэтому `doctor` разницы не видит.

**Предложение.** Хук `UserPromptSubmit` (или `SessionStart` плюс каждый `UserPromptSubmit`) сравнивает версию своего
каталога (`CLAUDE_PLUGIN_ROOT`) с `installed_plugins.json`. Если не совпадает, первой строкой контекста пишет: «сессия
на X, установлена Y — перезапустите Claude Code; запреты Y на эту сессию не действуют». Строку `doctor` тоже: версия
диспетчера/сторожа против установленной.

**Проверка.** Тест с подменённым `installed_plugins.json`.

### П3. `supervise.py --install` пишет PATH в plist

**Сейчас.** `supervise.py:168` `launchd_plist()` собирает plist без `EnvironmentVariables`. launchd запускает
диспетчер с PATH `/usr/bin:/bin:/usr/sbin:/sbin`, `claude` из `/opt/homebrew/bin` не находится, роли не стартуют.
В `docs/install-macos.md:43` PATH для ручного plist описан, а в `--install` его нет. В invoice это повторилось третий
раз (13.10: диспетчер мёртв 681 мин; 16.10; 27.10).

**Предложение.** `launchd_plist()` добавляет `EnvironmentVariables` с `PATH` (каталог `command -v claude`, каталог
python, `/usr/local/bin:/usr/bin:/bin`) и `CLAUDE_BIN`, если он задан. `doctor` — FAIL, если в plist нет PATH или
`claude` из него не находится.

**Проверка.** Тест на текст plist; `doctor` с plist без PATH даёт FAIL.

### П4. Коммиты CEO не уходят в main с пушем Судьи без приёмки

**Сейчас.** Судья по В-127 сам пушит принятое в main. Пуш берёт всю ветку, поэтому коммиты CEO в том же checkout
(`CLAUDE.md`, уставы) уходят вместе с принятым тикетом, хотя Судья их не видел. Так ушёл `a4d6a128`.

**Предложение.** Перед пушем Судьи сравнивать `origin/main..HEAD` со списком коммитов принятого тикета. Чужие коммиты
(префикс `[CEO]` или без тикета) — отказ с перечнем: «в пуше N коммитов вне TK-X — завести им тикет или пушить
отдельно». Второй вариант: правка CEO в `CLAUDE.md` или в уставах ставит тикет Судье сама, как `config set`.

**Проверка.** Тест с коммитом `[CEO]` поверх принятого: пуш отказан, в сообщении есть sha.

### Мелочи

- **`charter sync` без `--ref`.** Сейчас ref необязателен, и синк прошёл до того, как слово владельца легло в реестр.
  Для CEO сделать `--ref В-N` обязательным, как у `new`.
- **Тормоз запусков.** `doctor` в 17:16 — простой 26 мин из 10, весь он от `MAX_RUNS_PER_TICKET_HOUR`, лимит 12 по
  умолчанию (`dispatch.py:124`). Сегодня его съели длинные цепочки «правка в Figma → выгрузка → проверка» в одном
  тикете. Возможно, лимит стоит считать по времени сессии, а не по числу запусков. Отдельно это не мерили.
