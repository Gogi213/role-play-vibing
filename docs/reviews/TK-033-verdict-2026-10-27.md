## Пункт 3: страж уставов ослаб на `popd`

Заказ: расхождения (popd, cd -, $VAR) закрепить тестом до правки — то есть прежнее поведение сохраняется (гейт «результат в
результат»); разрешение менять поведение было только на пункт 4. Тест в PR закрепляет новое поведение, а не прежнее.

Проба (тестовый класс `test_charter_guard.CharterGuard`, хуки origin/main против ade68c7):

| команда | origin/main | ade68c7 |
|---|---|---|
| `cd .claude/roles; popd; cp /tmp/x judge.md` | BLOCK | pass |
| `cd .claude/roles && popd && cp /tmp/x judge.md` | BLOCK | pass |
| `pushd .claude/roles; popd; cp /tmp/x .claude/roles/judge.md` | BLOCK | BLOCK |

`popd` при пустом стеке каталог не меняет (bash — ошибка, pwsh Pop-Location — молча), так что после `cd .claude/roles; popd`
запись идёт в устав, а страж её теперь пропускает. В dguard «каталог неизвестен» — осторожная сторона (запрет); здесь
неизвестный каталог = «не устав», то есть «как dguard» переворачивает направление. Нарушает закрепление В-12 (CEO не правит
уставы руками).

Что сделать: после `popd` не терять каталог в сторону «разрешить» — например, оставить прежний `here` (как было), либо считать
`popd` без известного стека осторожно; тест из PR переписать на BLOCK для этих двух команд. Остальные пункты не трогать.
