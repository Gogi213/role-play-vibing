Алгоритм: варианты — оценка по сводному `totalTokens` из wf_*.json против суммы usage по ответам; замер — сумма по ответам даёт посчитать вид токенов и часы, сводка этого не даёт; выбран — по ответам, потому что только так разделяются кэш/выход и часы.

## 6. Непрерывность: почему в Ультракоде не бывает простоев (дополнение владельца к В-52)

Скрипты: `tools/ultracode_idle.py` (данные `ultracode-alpha-2026-11-idle.json`), `tools/plugin_gaps.py`. Главная сессия alpha 05.11 01:22 – 07.11 15:04 (3702 мин), 200 агентов.

**Лента времени (минуты):** работа главной без агентов 124 (3,3 %); главная + агенты 634 (17,1 %); главная ждёт, агенты работают 1778 (48,0 %); никто не работает 1166 (31,5 %). Агенты идут в 65 % времени, одновременно до 11.

**Простои.** 1125 из 1166 мин — девять промежутков ≥ 10 мин, и два из них — 893 мин:
- 06.11 05:52 → 13:32 (459 мин): «Your organization has disabled Claude subscription access» — внешний отказ, не механика.
- 05.11 06:52 → 14:07 (434 мин): ход закончился, ждали владельца (его реплика в 14:07).
- 05.11 19:38 → 20:50 (71), 22:17 → 23:16 (59) и др.: ход закончен, ждали реплику владельца. После вычета двух больших простой = 273 из 2809 мин (9,7 %).
Простоя «готовая работа есть, никто не работает» в ленте нет: между репликами владельца работа идёт сама.

**Механика (чем держится):**
1. Прогоны и тяжёлые команды запускаются в фоне; по завершении в очередь главной падает `<task-notification>` — 349 постановок в очередь против 90 реплик владельца. Главная просыпается по событию, не по таймеру.
2. Pipeline без барьеров: следующий этап стартует по готовности одного, не всей пачки (макс. 11 одновременно).
3. Следующий прогон запускается в том же ходе, где прочитан результат предыдущего (по ленте: уведомление → новый запуск в том же ходе; точное время не измерял).
4. Агенты долгие (часы), главная их не опрашивает — ожидание бесплатно по токенам.

**Плагин за ту же неделю** (логи тикетов, `plugin_gaps.py`): 03.11–07.11 79 записей, четыре промежутка ≥ 30 мин на 6530 из 6700 мин — но 5087 из них (04.11 02:40 → 07.11 15:27) это плагин выключен (В-42/В-43), не простой. Реальные: 03.11 04:11 → 04.11 02:19 = 1329 мин (22 ч: TK-105 принят, выпуск заведён только на следующую ночь — пример владельца); 03.11 01:35 → 02:56 (82 мин), 02:57 → 03:29 (32 мин). Счётчик `downtime.py` за все дни показал 0 мин, кроме 02.11 (stall 3,5 мин): он считает только «готовая работа есть, никто не работает» и не видит класс «влито, не выпущено при пустой очереди» и «событие есть, CEO не разбужен» (11 записей `ceo-не-разбужен`, из них 9 в 02:54:59 03.11 — сессия CEO не найдена в ListAgents).

**Что перенести в плагин (оценка снятого простоя):**
| механика | куда | что снимает |
|---|---|---|
| Пробуждение события: завершение тикета/CI/приёмки кладёт запись в очередь CEO и будит его (аналог task-notification), без таймера | диспетчер + побудка CEO (В-35 уже одобрил) | «влито, не выпущено» 22 ч → минуты; число таких дыр в неделю не считал (найдена одна — TK-105) |
