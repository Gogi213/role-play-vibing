# G-013: сдачи `[итог: pr]` с головой, которой нет на GitHub

**Вывод:** по логам найден один достоверный случай на 376 сдач (0,3 %) — TK-074, 31.10, 17,8 мин простоя; в alpha (259 сдач) достоверных нет, но логи не позволяют это доказать до конца.

## Метод
Скрипт `tools/unpushed_heads.py <.claude проекта> …` читает записи `[итог: pr] PR #N@sha` в `tickets/TK-*.md` и `tickets/archive/*-log.md`.
- **Достоверный залип** — позднейшая запись ceo/judge/engineer «коммит <sha> … не запушен | detached HEAD» именно про этот sha. Минуты — от сдачи до записи `ci` с этим sha, иначе до следующей записи тикета.
- **Медленный CI** (запись `ci` позже 10 мин) — считается отдельно: это не доказывает «не запушен».
- **Слабый признак** — нет строки «PR #N sha» в `ci_watch.run.log` (PR внутри окна журнала, записи `ci` нет). Журнал без времени и ротируется, поэтому в залипы не входит.
Сверки `git cat-file` по remote задним числом нет: голов прошлых сдач в remote после слияния и удаления веток уже не проверить.

## Примеры
- TK-074, 2026-10-31 23:03 — PR #184@e882ee4 лежал на detached HEAD в `.claude/worktrees/TK-074`; CEO заметил в 23:16, Инженер запушил в 23:17, CI зелёный 23:20. Простой 17,8 мин (до записи `ci`).
- alpha TK-090, 2026-10-08 — PR #46@d353a59, запись `ci` через 24,3 мин; TK-091 PR #50 — 31,7 мин. Это медленный CI, пуш не доказан.
- Слабый признак в alpha: 76 сдач без строки в `ci_watch`; журнал alpha, видимо, смешан с PR другого репозитория, как залипы не засчитаны.

## Чего не хватает
- Времени в `ci_watch.run.log` и истории remote-голов: без них не отличить «не запушен» от «CI не успел запуститься».
- Случаев, где Инженер сам исправил пуш без записи в тикете, не видно.

## Что дальше
Нужно решение владельца: нет. Дешёвая защита, если частота важна, — сверять `git ls-remote` с `--sha` при `result … pr`; решать CEO/Судье (0,3 % сдач).
