# Ожидания тикета (`wait_for`)

Долгую работу не держат сессией: тикет переводят в `status: waiting` с условием `wait_for`, а диспетчер сам проверяет условие и будит владельца тикета, когда оно выполнено.

## Формы условия

| форма | выполнено, когда |
|---|---|
| `host:<алиас>:<путь>` | файл по пути есть на машине (по ssh); алиасы `calc`, `vps`, `deck` (`deck:<путь>` — синоним `host:deck:<путь>`) |
| `host:<алиас>:unit:<имя>` | юнит systemd на машине не активен (остановился) |
| `file:<путь>` | файл есть локально |
| `ticket:<ID>` | указанный тикет дошёл до `status: done` |
| `ci-run:<владелец/репо>#<id прогона>` | конкретный прогон CI завершён (успех или красный — исход смотрит владелец). Прогон исчез (404) — сторож будит владельца. Нужен, когда ждёшь прогон, а не голову PR (`ci:`) |
| `job:<алиас>:<id>` | задание проекта завершилось (`done`); упало/исчезло — сторож будит владельца с хвостом лога. Состояние даёт адаптер `RPV_JOB_STATE_CMD` |
| `at:<время ISO>` | наступило время (без пояса — местное). Суточные наблюдения: сторож жизни такие ожидания не будит и не считает зависшими; в Диспетчерской — «ждёт до 09.10 02:00, осталось N ч». Метка-файл и задание планировщика не нужны |

Файл хода `*.json` (`{"done": N, "total": M, …}`) считается готовым при `done >= total`.

Условие и статус ставит одна команда:

```
python <плагин>/.claude/dispatcher/tickets.py --project <проект> wait <ID> <условие> [--on-met ...]
```

Форма проверяется при записи.

## Машины

Адреса машин — только из окружения: `RPV_CALC_HOST`, `RPV_VPS_HOST`, `RPV_DECK_HOST` (что понимает `ssh`: `user@host` или алиас из `~/.ssh/config`), плюс `RPV_DECK_KEY` и `RPV_DECK_KNOWN_HOSTS`. Каталог файлов хода на машине — `RPV_PROGRESS_DIR` (по умолчанию `~/rpv/progress`). Не задан хост — условие «не выполнено» и строка в `dispatch.err.log`.

Вызов ssh идёт с `BatchMode=yes` — нужен ключ без парольной фразы (или ssh-agent). Удалённая сторона — Linux: проверки выполняются командами `test`, `cat`, `systemctl`, `grep`.

## Как диспетчер узнаёт, что условие выполнено

- **С шиной** ([bus.md](bus.md)): события `юнит.остановлен/упал`, `задание.готово`, `файл.появился` закрывают `wait_for` сразу. Сторож машины читает `watch.list` из каталога файлов хода и шлёт `файл.появился`.
- **Ssh — не основной путь** (с шиной): первая проверка нового условия, затем сверка раз в `RPV_DISPATCH_WAIT_RECON_S` (300 с) одним ssh на машину. Сверка заново регистрирует путь в `watch.list` сторожа машины; если она закрыла условие, а события с машины не было, на машине из `RPV_WATCHED_ALIASES` диспетчер шлёт тревогу `recon-miss`. Пока шина лежит, тревога `recon-miss` не шлётся; условия закрывает та же сверка. Файл хода (`*.json` в `RPV_PROGRESS_DIR`) в `watch.list` не регистрируется — его закрывает только `done >= total`; для событий `задание.готово` задавайте абсолютный `RPV_PROGRESS_DIR`. Все ssh-вызовы пишутся в `.claude/dispatcher/ssh-calls.log`.
- **Без шины или пока она лежит:** работает та же сверка раз в `RPV_DISPATCH_WAIT_RECON_S` в потоке `wait-poller` (тик не блокируется); отдельного аварийного опроса нет.
- Сторож (`watch.py`) разбирает мёртвые цели без модели: хост недоступен, юнита или файла нет — и считает застой.

## `on_met`

`--on-met "python tools/x.py арг"` — когда условие выполнено, диспетчер сам запускает эту команду вместо пробуждения роли. Допустимы `python`, `python3` или `bash` и скрипт под `tools/` или `.claude/` проекта, отслеживаемый git (пути с прямыми слешами). Результат пишется в журнал тикета. Отказ, сбой или таймаут (`RPV_DISPATCH_ON_MET_TIMEOUT_S`, 120 с, дерево процессов убивается) — диспетчер будит владельца тикета; то же после трёх `on_met` подряд без запуска роли. `on_met` не закрывает тикет и не зовёт Судью: такой тикет возвращается в `in_progress`. После таймаута запуска роль продолжает **ту же сессию** (`--session-id`).

## Защита от циклов

`tickets.py wait` отказывает, если `ticket:<ID>` замыкает цепочку ожиданий: каждый ждёт следующего, и никто не пойдёт. Уже существующий цикл диспетчер сообщает CEO раз в сутки. Ждите результат (`file:`, `host:…`), а не тикет, или разорвите цепочку.

Тикет в `waiting` без условия и без `--next` диспетчер не оставляет: через 10 минут это считается простоем, а владельца тикета диспетчер будит сам — см. [reliability.md](reliability.md).
