## Оставляем как есть

Ядро уже совпадает с практиками рынка: одна задача — одна свежая сессия, состояние в файлах, переход по таблице, доказательство на каждом шаге.

1. **Тикеты `.claude/tickets/*.md` — единственное состояние задач.** Диспетчер читает шапку, прозу не читает (`ticket.py`, `templates/roles/README.md`) (15).
2. **Новая сессия на каждое пробуждение роли.** `--resume` — только повтор после таймаута 20 мин (`dispatch.py`, PR #100, #101).
3. **Один запуск на роль и один на тикет** по умолчанию: `RPV_DISPATCH_ROLE_PARALLEL` пуст — предел 1 (`dispatch.py`) (13).
4. **Итог шага с доказательством.** `done` — только с существующим файлом, `pr` — номер и sha; тикет Судьи закрывается только по файлу, закоммиченному в git (`routes.py`, TK-225) (2).
5. **Кого будить дальше, решает таблица** `routes.py`, а не текст записи и не CEO.
6. **Тормоза циклов.** После 2 возвратов ревьюера тикет закрывается «не сделано» с остатком; 12 запусков без смены статуса или 2 холостых — `blocked`; не больше 6 запусков на тикет в час, пауза от 60 с (`dispatch.py`) (1).
7. **`--ref` при создании тикета**: цитата владельца от 5 знаков или «В-##»; похожий тикет за последний час — отказ (`tickets.py`) (1).
8. **Stop-хук** не даёт роли закончить запуск без записи в тикет (`stop_result.py`).
9. **Страж `delete_guard.py`** на Bash, PowerShell, Write, Edit: удаление и перезапись вне своей папки, `git reset --hard`, `git push --force/--delete/--mirror`, правка ролями `.claude/settings*.json` и `.git`. Сбой стража — отказ (14).
10. **`wait_for`** (файл, юнит, тикет, CI, задание, время) со сроком `--by` для долгих ожиданий: срок прошёл на 15 мин — сторож будит роль (`tickets.py`, `watch.py`) (12).
11. **Автовлитие PR** только при вердикте Судьи на текущей голове, зелёном CI и сливаемом PR (`merge_rule.py` + `ci_watch.py`, включается `RPV_CI_REPO`) (2).
12. **Счётчик простоя**: минуты в сутки «готовая работа есть, никто не работает», порог 10 мин в сутки (`downtime.py`) (10).
13. **Учёт токенов** по каждому запуску в `runs.log`, сводка по тикету, роли и причине пробуждения (`usage.py`) (11).
14. **Помощники внутри сессии роли**: `reader` (Haiku, только чтение, сводка со ссылками) и `coder` (Sonnet) (`agents/`).

## Доделываем: в коде есть частично

Здесь основная работа V2: критерии 2, 4 и 6 сейчас держатся на тексте уставов, а не на коде.

1. **Судья на каждом выводе.** Ревьюера по умолчанию нет (`tickets.py new`), и `done` исследователя без `--reviewer judge` закрывает тикет без проверки (`routes.py`); PR с кодом уходит к Судье всегда. Сделать Судью умолчанием для любого `done`, кроме механических задач Haiku (2).
2. **Поводы вопроса владельцу.** В коде — деньги, видимое, необратимое, бизнес-правило (`routes.py`, `OWNER_REASONS`); направления нет, хотя в `templates/brief/preferences.md` оно есть. Свести к четырём поводам владельца: деньги, направление, необратимое, бизнес-правило (5).
3. **Реестр решений владельца.** `--ref` принимает «В-##», но реестра этих решений в плагине нет: их пишет CEO в CLAUDE.md и автопамять (`ceo.md`), часть вшита в код комментариями («владелец 27.09», «В-153»). Запрет ролям писать CLAUDE.md есть только в тексте устава, страж его не держит. Сделать один файл решений: правит владелец или CEO его дословной цитатой, страж закрывает запись ролям, файл подключён к CLAUDE.md импортом `@` (вставка SessionStart-хука ограничена 8000 знаков, `role_context.py`). Судья возвращает работу, которая противоречит записи (6).
4. **Числа.** «Изобретённое число запрещено» — в уставе (`templates/roles/README.md`); Судья по уставу сверяет 2–3 ключевых числа с исходными файлами (`judge.md`). Механики нет. Сделать: вердикт по сдаче с числами — с таблицей «число · файл, откуда оно»; `accept` без неё — отказ в `routes.check` (4).
5. **Сроки.** `--by` у долгих ожиданий обязателен, просрочку ловит сторож (`watch.py`). Но промахи нигде не копятся, а CEO по уставу называет «сроки числом на каждый шаг» без проверки (`ceo.md`). Сделать: записывать «назван / факт» по каждому сроку и показывать долю сбывшихся в ежедневном отчёте (4).
6. **Ежедневный отчёт.** Шаблон `templates/brief/` есть (PR #97): предпочтения только для чтения, закладка, журнал, «сбой источника ≠ тишина», перепроверка чисел. Код его не читает, а `/rpv-init` копирует только уставы ролей. Сделать: init копирует шаблон, отчёт собирается из принятых Судьёй результатов и уходит одним сообщением (2, 9).
7. **Присмотр.** `supervise.py --install` уже ставит штатный планировщик ОС раз в 5 мин (Планировщик заданий Windows, systemd timer, launchd), но это отдельный ручной шаг (README). Сделать частью `/rpv-init` (10, 17).
8. **Токены.** Сводка `usage.py` делит токены по тикету, роли и причине пробуждения, но не отвечает, сколько ушло на механику. Добавить эту строку (11).

## Добавляем: в коде нет

Целей и реестра ошибок в репозитории нет: поиск по `goal`, `G-`, `errors`, «регресс» пуст.

1. **Цели.** Файл на цель: что нужно владельцу, критерии приёмки, бюджет, время постановки и принятия. `--ref` тикета указывает на цель или на решение владельца. Время «цель → принятый результат» считается из этих отметок и идёт в ежедневный отчёт (1, 3).
2. **Реестр ошибок с проверкой.** Сейчас есть только блокнот роли до 4 КБ и конспекты сессий (`role_memory.py`): исправленная ошибка ничем не закреплена после очистки контекста. Ошибка считается исправленной, когда к её записи приложена проверка — тест или скрипт; Судья прогоняет весь набор при каждой приёмке (7).

## Не берём с рынка

Ни один готовый инструмент не закрывает слой владельца, а большинство добавляет механику (данные о продуктах — из отчёта исследования, не из кода).

1. **Agent Teams.** Функция экспериментальная, в plan mode тратит примерно в 7 раз больше токенов, одна команда на сессию, памяти между сессиями нет. Параллельное чтение уже закрывает помощник `reader`, а параллельная запись — то, от чего мы уходим.
2. **Ruflo (claude-flow).** Рои, консенсус и векторная память — противоположность критериям 16 и 14; их цифры никто независимо не проверял.
3. **CrewAI, AutoGen, MetaGPT, ChatDev.** Ролевые команды, на них сняты отказы MAST; переезд — переписывание.
4. **LangGraph.** Контрольная точка на каждом шаге уже есть в файлах тикетов; переезд на библиотеку — новый проект.
5. **Claude Squad, ccpm.** Worktree на тикет уже есть: копия в `.claude/worktrees/<тикет>`, диспетчер убирает её при закрытии (`worktree_hygiene.py`).
6. **Managed Agents и Routines** — не в V2. Routines в research preview, у облачной рутины минимальный интервал час; хранилища памяти Managed Agents на старте не работали с собственными песочницами. Кандидат на пилот после V2, если нужна работа без включённого ПК.

## Отрезаем из текущего

Механика сейчас — около 13,4 тыс. строк кода и 12,1 тыс. строк тестов: диспетчер 8 937, хуки 3 035, табло 806 плюс 790 строк html/css/js, шина 584. За 6–13.10 по git log — 404 коммита и 57 версий. Вычитание уже идёт: TK-236, шаг 1, минус 971 строка (16).

1. **Шина** (`.claude/bus`, `bus_link.py`; выключена без `RPV_BUS_URL`). Без неё ssh-сверка раз в 300 с уже работает, но видит только `systemctl is-active` и не отличает падение от успеха: `jobrun.sh` запускает юнит с `--collect`, и упавший юнит удаляется вместе с кодом выхода. Взамен: `jobrun.sh` пишет `$SERVICE_RESULT` и `$EXIT_STATUS` в `runs/<unit>.rc` через `ExecStopPost`, тикет ждёт этот файл формой `host:<машина>:<путь>` (на машине не проверено). Задержка — до 5 мин (`RPV_DISPATCH_WAIT_RECON_S`). Сигналы CEO и так идут запасным путём через `ceo-inbox.md` (12, 16).
2. **Табло** (`.claude/board`, `board_push.py`, `view2.py`, `pulsedata.py`; включается `RPV_BOARD`). Показывает «N из M шагов», а Haiku-пересказы процессов (`plainify.py`) при работающей отправке включены по умолчанию. Вместе с табло уходят ответы владельца кнопками (`pulse_answer`) — отвечать через CEO. Взамен — ежедневный отчёт и одна тревога (8, 9, 11).
3. **Автовыпуск самого плагина** (`release.py auto`; его зовёт `merge_rule.py`, когда влит PR в репозиторий плагина): тег, обновление установленного плагина, перезапуск служб, откат. Это цикл, в котором команда правит и перевыпускает собственный инструмент. При заморозке выпуск — вручную, `release.py bump` (16).
4. **Механические сигналы CEO**: «диспетчер слеп», `idle-slo`, «нет-хода», «цикл-ожиданий», `recon-miss`, `stop-failed`, `parse-error` (`dispatch.py`, `blind.py`). Свести к одной тревоге владельцу «готовая работа стоит» — её уже считает `downtime.py`; остальное — в лог (5, 8).
5. **Правила проекта alpha внутри стражей**: `heavy_guard.py` (замок замеров, `/data/alpha`, `alsched`, `benchrun`), в `delete_guard.py` — Storage Box, `root/`, `deep/`. Вынести в настройки проекта; PR #101 отложил это до решения владельца (17).
6. **Россыпь переменных**: в коде около 128 имён `RPV_*`, в `docs/configuration.md` описано 87. Оставить несколько, остальное — константы или один конфиг-файл (17).
