# Настройка: переменные окружения

Все переменные плагина называются `RPV_*`. Пустое значение считается «не задано». Настройки, которые должны ехать вместе с проектом (защищённые пути), лежат не в окружении, а в файле проекта `.claude/rpv.json` ([ниже](#защищённые-пути--clauderpvjson)).

Службу запускает `/rpv-start` (`start.py`): она получает только `RPV_*`, `CLAUDE_BIN`, `CLAUDE_PROJECT_DIR`, `CLAUDE_CONFIG_DIR` и `PATH` (на POSIX); секреты (`ANTHROPIC_*`, токены) не переносятся. Присмотр ОС запоминает `RPV_*` и `CLAUDE_*` в `supervise.env.json` без секретов — [reliability.md](reliability.md#присмотр-за-диспетчером-и-сторожем).

Краткая таблица главных переменных — в [README](../README.md#настройка).

## Проект и роли

| переменная | по умолчанию | смысл |
|---|---|---|
| `RPV_PROJECT` | — | корень проекта; порядок поиска: `--project`, `RPV_PROJECT`, `CLAUDE_PROJECT_DIR`, ближайший каталог вверх от текущего с `.claude/roles` |
| `CLAUDE_BIN` | `claude` из `PATH` | путь к Claude Code CLI |
| `CLAUDE_PROJECT_DIR`, `CLAUDE_CONFIG_DIR` | — | задаёт Claude Code; переносятся службам |
| `RPV_ROLE` | — | роль сессии; выставляет диспетчер при запуске роли (хуки читают её, чтобы вставить устав) |
| `RPV_TICKET` (`RPV_TICKET_ID`) | — | тикет запуска; выставляет диспетчер |
| `RPV_STATE_DIR` | `<проект>/.claude/roles/.state` | метки сессий и состояние хуков |
| `RPV_LOG_DIR` | `<проект>/.claude/roles/log` | конспекты сессий ролей (пишет хук `SessionEnd`) |
| `RPV_DISPATCHER_DIR` | `<проект>/.claude/dispatcher` | где хуки ищут состояние диспетчера |
| `RPV_CONTEXT_WARN_TOKENS` | `450000` | порог размера контекста, с которого CEO предупреждают о клире (45 % окна в 1 млн токенов) |

## Сторож (`RPV_WATCH_*`)

| переменная | по умолчанию | смысл |
|---|---|---|
| `RPV_WATCH_INTERVAL` | `120` | цикл, с |
| `RPV_WATCH_REPEAT_HOURS` | `2` | повтор тревоги, пока проблема не снята, ч |
| `RPV_WATCH_LONG_REPEAT_HOURS` | `24` | повтор для редких видов находок (сироты, `blocked`, `needs_owner`), ч |
| `RPV_WATCH_ORPHAN_HOURS` | `2` | через сколько часов без новой записи открытый тикет считается сиротой |
| `RPV_WATCH_DEAD_WAIT_STRIKES` | `2` | подряд мёртвых проверок цели `wait_for` до действия |
| `RPV_WATCH_AT_GRACE_MIN` | `30` | допуск (мин) после времени `wait_for: at:<ISO>`: позже тикет всё ещё `waiting` значит диспетчер не разбудил — сторож считает цель мёртвой и будит владельца. Диспетчер проверяет ожидания каждые ~15 с, сторож — раз в ~2 мин; 30 мин — запас на простой диспетчера |
| `RPV_WATCH_EMPTY_WAIT_STRIKES` | `3` | подряд проверок сторожа, когда тикет `waiting` без `wait_for` и без `next`, до пробуждения владельца (ждать нечего, производителя нет; повтор → blocked). Диспетчер берёт `next` за ~15 с, сторож ходит раз в ~2 мин — 3 цикла (~6 мин) отсекают гонку со снятием условия |
| `RPV_WATCH_MET_GRACE_MIN` | `15` | допуск (мин): условие `host:`-пути выполнено (файл есть; файл хода — done>=total), а тикет всё ещё `waiting` — диспетчер не разбудил, сторож будит владельца. Диспетчер сверяет раз в 300 с (`RPV_DISPATCH_WAIT_RECON_S`), 15 мин = 3 сверки без реакции |
| `RPV_STRAY_CMD` | не задан | адаптер проекта (по ssh на машине алиаса): строка `тикет<TAB>описание` на прогон мимо планировщика поверх чужого задания; сторож будит владельца тикета записью, без тикета — CEO. Не задан — проверки нет |
| `RPV_WATCH_STRAY_WAKE_REPEAT_HOURS` | `2` | не чаще одного сигнала о том же прогоне мимо планировщика за N ч: замер идёт часами, напоминание раз в 2 ч, не спам |
| `RPV_JOB_STATE_CMD` | не задано | адаптер формы `wait_for: job:<алиас>:<id>`: команда с `{id}`, выполняется по ssh на машине алиаса; 1-я строка вывода `running\|queued\|done\|failed\|missing`, далее хвост лога. Не задан — форма не проверяется, сторож пишет «не проверить» после `RPV_WATCH_SSH_FAIL_STRIKES` циклов. Падение (`failed`) будит владельца тикета сразу (оно однозначно); `missing` — после `RPV_WATCH_DEAD_WAIT_STRIKES` циклов подряд (≈ 2 × `RPV_WATCH_INTERVAL` = 4 мин: задание могло ещё не записаться). Причину по хвосту лога одной строкой пишет Haiku (`haiku_aux`), если он есть |
| `RPV_WATCH_STALL_RUNS` | `2` | подряд таймаутов или холостых запусков до блока |

## Машины и ssh

Машина в `wait_for: host:<алиас>:…` — любой алиас из `~/.ssh/config`: адрес, пользователя, ключ и `known_hosts` берёт сам `ssh`. Переменных для хостов и ключей у плагина нет ([wait-for.md](wait-for.md#машины)).

Переменные `tools/jobrun.sh` — их задают на самой машине, в окружении запуска скрипта ([wait-for.md](wait-for.md#задание-на-машине-jobrunsh)):

| переменная | по умолчанию | смысл |
|---|---|---|
| `RPV_RUNS_DIR` | `/var/lib/rpv/runs` | куда `jobrun.sh` пишет файл итога задания `<unit>.rc` (и `<unit>.log` без systemd) |
| `RPV_JOBRUN_MODE` | сам: `systemd`, если есть `/run/systemd/system` и `systemd-run`, иначе `trap` | режим запуска задания: юнит systemd с `ExecStopPost` или фоновая оболочка с `trap` |

## Отчёт владельцу и тревога

Сообщения владельцу шлёт сам плагин (диспетчер), не сессия CEO: ежедневный отчёт ([README](../README.md#ход-работы-владельцу)) и тревога «работа стоит» ([reliability.md](reliability.md#счётчик-простоя)). Бот — только отправка; токен и чат хранятся в окружении машины владельца, не в репозитории. Проверка связи: `python <плагин>/.claude/dispatcher/notify.py --project <проект> test`.

| переменная | по умолчанию | смысл |
|---|---|---|
| `RPV_TG_TOKEN` | не задан | токен бота от @BotFather. Не задан (или не задан чат) — Telegram не настроен: сообщения не уходят, строка «не отправлено» в `notify.log`, отчёт всё равно пишется в `.claude/dispatcher/reports/<дата>.md` |
| `RPV_TG_CHAT` | не задан | идентификатор чата владельца (число из `getUpdates` после первого сообщения боту) |
| `RPV_REPORT_AT` | `10:00` | время ежедневного отчёта, `ЧЧ:ММ`, местное время машины, где работает диспетчер. Не разобрать — `10:00`. Диспетчер стоял в это время — отчёт уходит на первом тике после и один раз |

## Страж удаления

Хук `PreToolUse` (`hooks/hooks.json`) ловит Bash, PowerShell, Write, Edit, MultiEdit и NotebookEdit: удалять и перезаписывать можно только внутри проекта и scratchpad сессии. Работает в проектах с `.claude/roles`. Без настроек на удалённых машинах удалять нельзя нигде. Правил конкретного проекта (каталоги данных, серверы, замки замеров) в плагине нет: что нельзя трогать, проект объявляет сам — файлом ниже.

### Защищённые пути — `.claude/rpv.json`

Список шаблонов путей, которые не удаляет и не перезаписывает никто — ни роль, ни CEO. Лежит в проекте, ключ `protected_paths`:

```json
{
  "protected_paths": ["data/raw/**", "backups", "*.pem", "/mnt/archive"]
}
```

Файл, а не переменная окружения, — чтобы защита ехала вместе с проектом: в репозитории, на другой компьютер и в другой клон, а не жила в настройке одной машины. Нет файла или ключа, список пуст — защиты нет, всё как раньше. Другие ключи в файле плагин пока не читает.

| шаблон | что защищено |
|---|---|
| `deep`, `*.pem` | файл или каталог с таким именем на любой глубине (как в `.gitignore`) |
| `data/raw`, `data/**/secret` | путь от корня проекта; `*`, `?`, `[…]` — внутри одного имени, `**` — любое число каталогов |
| `/mnt/archive`, `~/keys`, `c:/data` | именно этот путь (`~` — домашний каталог) |

- Защищён сам путь и всё внутри. Каталог, в котором защищённое лежит, при удалении тоже закрыт (`rm -rf data` при `data/raw`), если шаблон начинается с пути; шаблоны-имена и `**/…` родителей не закрывают. Регистр не различается, хвостовой `/` не нужен. Маска в команде (`rm data/*`) считается «может задеть».
- Закрыты: удаление и перенос (`rm`, `mv` источника, `find -delete`, `rsync --delete`, `git clean`, `shutil.rmtree`, `Remove-Item` и подобные) и перезапись существующего файла (`>`, `tee`, `cp`/`mv` поверх, `truncate`, `dd of=`, Write/Edit/MultiEdit/NotebookEdit). Новый файл на этом месте ничего не затирает — можно; дописывание `>>` тоже.
- По ssh корень проекта неизвестен: шаблон с путём ищется на удалённой машине на любой глубине, абсолютный — как записан.
- Файл `.claude/rpv.json` запуску роли менять нельзя (как настройки Claude Code): снять защиту может только CEO по слову владельца.
- Файл есть, но не читается, не JSON, `protected_paths` — не список непустых строк или в шаблоне `..` — страж **отказывает любому удалению и перезаписи** с причиной, пока файл не исправят (fail-closed: неизвестно, что защищено). Читать, создавать новые файлы и править сам `.claude/rpv.json` (CEO) можно. В тексте отказа названы файл и шаблон, который сработал.

### Прочие переменные стража (`RPV_GUARD_*`)

| переменная | смысл |
|---|---|
| `RPV_GUARD_REMOTE_ROOTS` | каталоги, где можно удалять на любых удалённых машинах |
| `RPV_GUARD_STAGE` | оперативная стадия — каталог, целиком разрешённый для удаления |
| `RPV_GUARD_FORBIDDEN_HOSTS` | закрытые хосты и IP, через запятую: там нельзя ничего |

`git reset --hard` и `git clean -f` страж пропускает только в каталоге вне основного дерева, заданном явным путём; `git push --force` — никогда. Публикации (выпуск, слияние PR, пуш в main/master и теги, публикация пакетов) запуску роли закрыты, пока в шапке его тикета нет `allow: publish (В-N)` (`tickets.py allow`, только CEO); настроек для этого нет.

## Служебные
