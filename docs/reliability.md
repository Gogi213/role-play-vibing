# Надёжность: присмотр, простой, инвариант хода

Что не даёт работе встать и как увидеть, если она встала. Быстрая проверка — `/rpv-doctor` ([README](../README.md#диагностика)).

Сигналы и «строки CEO» ниже идут по [стандарту сигналов](signals.md): при шине — события в очереди `ceo`, без шины и при её сбое — `ceo-inbox.md`.

## Присмотр за диспетчером и сторожем

```
python <плагин>/.claude/dispatcher/supervise.py --install [--project <проект>]
python <плагин>/.claude/dispatcher/supervise.py --uninstall [--project <проект>]
```

`--install` регистрирует в ОС задание, которое раз в 5 минут проверяет сердцебиение (`state.json` / `watch-heartbeat.json` старше 10 минут или процесса нет) и поднимает службу через `start.py` (WMI / systemd / `Popen`). Строки — в `<проект>/.claude/dispatcher/supervise.log`. Порог возраста сердцебиения — `RPV_SUPERVISE_STALE_S` (600).

| ОС | задание |
|---|---|
| Windows | Планировщик заданий, каждые 5 минут |
| Linux | `systemd --user` timer (`OnBootSec=1min`, затем каждые 5 минут) |
| macOS | launchd (`RunAtLoad`, `StartInterval` 5 минут) |

Окружение `RPV_*` / `CLAUDE_*` запоминается в `supervise.env.json` (он в `.gitignore`): планировщик окружение сессии не наследует. Секреты по окончанию имени (`…_TOKEN`, `…_SECRET`, `…_PASSWORD`, `…_API_KEY`) в файл не пишутся; пороги (`…_TOKENS`) и пути (`…_DECK_KEY`, `…_FILE`) — пишутся, поэтому токен шины давайте файлом `RPV_BUS_TOKEN_FILE`. Снять присмотр — `--uninstall`.

## Счётчик простоя

Диспетчер каждый тик учитывает минуты в сутки (`state.json` → `downtime`, хранится 14 суток):

- **готовая работа без исполнителя** — есть что запускать, а никто не работает;
- **роль ждёт без условия** — тикет `waiting` без `wait_for` и без `--next` дольше 10 минут;
- **молчание диспетчера при работе** — тики не шли, пока в очереди или в запуске была работа;
- **тормоз** — пауза между запусками тикета по `RPV_DISPATCH_MAX_RUNS_PER_TICKET_HOUR` (признак петли).

Пауза по лимиту (429) считается отдельно и в SLO не входит. SLO — `RPV_IDLE_SLO_MIN` (10 минут в сутки); превышение — одна тревога в сутки: событие шины `служба.простой.превышен` → CEO (шины нет или она недоступна — строка `idle-slo` в `ceo-inbox.md`, без дубля). `/rpv-doctor` показывает сегодняшний счёт и адрес шины, с которым живёт диспетчер.

## Пауза по лимиту (429)

Ответ `429` «session limit · resets …» — не провал запуска: диспетчер ждёт до сброса, а блоки по холостым ходам снимаются сами. Пауза считается от конца запуска, а не от разбора ответа, и не длиннее часа: дальше идёт пробный запуск (429 бесплатен), новая метка сброса — новая пауза.

## Инвариант «у открытого тикета есть ход»

Открытый тикет (`waiting`, `in_review`) всегда должен иметь следующий ход. Ходом считается: роль запущена; задан `next`; у `waiting` годный `wait_for`; есть вопрос владельцу без ответа (`ask.py`); передача CEO (`--next ceo`) ждёт ответа CEO.

Нет хода дольше `RPV_DISPATCH_INVARIANT_GRACE_S` (600 с от `updated` и от последней записи журнала) — диспетчер будит владельца тикета сам (`status: in_progress` и запись диспетчера) и один раз за эпизод пишет строку CEO вида `нет-хода`. Причины: `waiting` без `wait_for` и без `next`; `wait_for` не понят; `in_review`, где последняя запись — ревьюера, статус не сменён и `next` не задан. Передача CEO без ответа дольше грейса — одна повторная строка CEO (`ждёт-ceo`), владельца не будим: ход за CEO.

Цикл ожиданий `ticket:<ID>` отказывается при записи и сообщается CEO, если уже существует — [wait-for.md](wait-for.md#защита-от-циклов).

## Итог шага и маршруты

Роль сдаёт шаг одной командой `tickets.py result <ID> <итог> --why «…»` (≤ 200 знаков) и доказательством по типу; диспетчер текст записей не читает, кого будить — таблица в `routes.py`. Неполная команда — отказ в сессии роли, ничего не пишется.

| итог | кто | доказательство | дальше |
|---|---|---|---|
| `done` | исследователь, инженер | `--path` (существует на диске) | ревьюер (`in_review`), нет ревьюера — `done` |
| `pr` | инженер, исследователь | `--pr N --sha H` | `in_review`, next — ревьюер (Судья); номер — в `pr:` шапки |
| `accept` | Судья | `--pr N --sha H [--repo <владелец/репо>]` (репо — --repo или RPV_CI_REPO, без догадки по cwd; PR и голова сверяются у GitHub, нет — отказ) либо `--path <артефакт проверки>` (без PR) | PR: `accepted:` (список), `waiting` + `wait_for: merged:<репо>#N`, вливает merge_rule, после влития владелец будится (done или следующий шаг), Судья — нет; без PR: `done`, если последний итог владельца — done, иначе `in_progress` + next владелец (проверка перед необратимым шагом) |
| `return` | Судья | `--sha H` либо `--path <артефакт проверки>` | `in_progress`, next — владелец |
| `blocked` | любая | — | `blocked`, next — CEO |
| `ask-owner` | любая | — | `needs_owner`, next — CEO |
| `wait` | любая | `--form` (годная форма wait_for) | `waiting` + `wait_for` |

## Прогон на выносливость

```
python <плагин>/.claude/dispatcher/endurance.py [--rounds N | --hours H] [--idle-max S] [--seed K] [--keep] [--modes base,bus,reboot,watch]
```

Настоящий диспетчер в подпроцессе, фейковые роли и сбои. Раунд — 7 тикетов, роли ведут себя по плану (успех, 429, молчит, без статуса, `waiting` без условия, долгая работа); посреди раунда диспетчер жёстко убивается — во время долгой роли и в паузе лимита — и поднимается заново. Режимы сбоев идут по кругу: `base`; `bus` — падение шины, spool, ложное событие юнита; `reboot` — перезагрузка; `watch` — kill сторожа и диспетчера, и настоящий `supervise` поднимает обоих.

Критерий раунда: все тикеты `done`, 0 `blocked`, у каждого `done` есть строка в `ceo-inbox.md` (0 потерянных сигналов), самый долгий простой («есть готовая работа, никто не работает», вне паузы лимита) не больше `--idle-max`. Код возврата 0 — критерий выполнен. Ночью то же гоняет workflow [`endurance`](../.github/workflows/endurance.yml) (вручную — с параметром `hours`, по умолчанию 2).
