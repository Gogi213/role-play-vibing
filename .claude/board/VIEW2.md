Источники: план шагов — `.claude/pulse/plans/<ID>.json` (пишет исполнитель через `tools/pulse/plan.py`);
вопросы — `.claude/pulse/questions/<id>.json` (`tools/pulse/ask.py`); ход шагов на серверах — `/data/progress/*.json`
(поле `step_n` — номер шага плана); машины, процессы без хозяина — сборщик; тексты по-людски — Haiku (`plainify.py`).
Ответ владельца (кнопка или клавиша) — `ask.py answer <id> <key>` / MCP `pulse_answer`.

Уточнения сборщика (03.10, `view2.py`): `for.text` может быть пустым (плана нет); `feed` — по возрастанию времени, свежие
внизу, ≤ 8 (Haiku-строки v1 + завершённые шаги плана + вопросы/ответы); у шага без плана — один шаг из текущего состояния;
у вопроса процесс может быть не тикетом (`orphans-<машина>`); `pulse_answer {id, key}` — ответ владельца (MCP).

## Волны (04.10)

- **Внутри процесса.** У шага плана необязательное `after` (номера более ранних шагов; по умолчанию — предыдущий шаг,
  у первого — ничего): `wave(шаг) = 1 + max(wave(after))`, без `after` (пустой список) — волна 1. Шаги одной волны идут
  параллельно: рисовать столбиком друг под другом; в подробном виде — колонка «волна». Запись: `plan.py set … --step
  "название|кто|где|для чего|after=2,3"` (`after=` без номеров — стартует сразу; ссылаться можно только на более ранние
  шаги, лишние номера сборщик отбрасывает). В `view2` `after` и `wave` есть у каждого шага (у процессов без плана и
  «без хозяина» — цепочка).
- **Между процессами.** В шапке тикета необязательная строка `depends: TK-042, TK-043`; `wave(процесс) = 1 + max(wave(depends))`.
  Берутся только процессы, показанные на табло (закрытый, остановленный или не показываемый тикет — не ждём); цикл не ломает
  расчёт. Обзор группируется по `waves[]`: заголовок — `label` («ВОЛНА 1 · 2 процесса параллельно», «ВОЛНА 2 · ждёт волну 1»,
  «… · готова»); «без хозяина» — отдельная группа в конце, без номера.

## Состояния шага и процесса (04.10)

| state | по-людски | цвет | откуда |
|---|---|---|---|
| `done` | готово | зелёный | план / ход сервера 100 % |
| `run` | делается | синий #6AA9FF | план / ход сервера |
| `review` | проверяется | фиолетовый #B79CF5 | шаг `who=судья` в `run`; тикет в `in_review` (шаг `run` исполнителя, а если активных нет — первый впереди: шаг судьи, иначе первый); явный `plan.py step … review` |
| `repair` | чинится | оранжевый #F29A4B | последняя запись `judge` в логе с «вернуть/возврат», тикет не сдан снова (status ≠ `in_review`, не `done`) — шаг `run` исполнителя (инженер/исследователь); явный `plan.py step … repair` |
| `wait` | ждёт вас | жёлтый #F2B84B | вопрос владельцу / «ждёт» |
| `bad` | проблема | красный | «без хозяина», нет связи |
| `todo` | впереди | серый | — |

Состояние процесса — по приоритету `bad` > `wait` > `repair` > `review` > `run`, иначе `done` (все шаги) / `todo`.
Шапка: «готово N · делается M · проверяется K · чинится L · ждут вас Q» — `counters.done / run / review / repair / wait`.

## Итог процесса, общий прогресс (04.10)

- **`summary`** — одна строка по-людски: «что стало возможно» (Haiku, `plainify.py`, вид `psum`: вход — название, шаги с
  состояниями, последняя запись тикета; без номеров и жаргона) + « — N из M готово» (считает сборщик, у процесса с планом).
  Кэш по хэшу названия и шагов с состояниями: модель зовётся только когда меняется состояние шагов; пока она отвечает,
  показывается прежняя строка. Нет ответа / нет Haiku — `null`.
- **`progress.pct`** — сумма весов шагов (шаг = 1; не готовый шаг с `pct` — `pct/100`) / число шагов по всем процессам-тикетам
  (процессы «без хозяина» не считаются). Не 100, пока что-то не готово.
- **`progress.eta`** — вилка 0,75–1,4 × сумма `eta_min` не готовых шагов критической цепочки (самый длинный по `eta_min` путь
  через `after` шагов и `depends` процессов); есть только при ≥ 2 замерах (шагов цепочки с `eta_min`), иначе `null`.
- **`progress.spent_min`** — «прошло» в рабочем времени: события (записи логов процессов, начало/конец шагов плана,
  вопросы и ответы) по возрастанию; промежуток между соседними > 45 мин засчитывается как 45, последний — до «сейчас» тоже.

## Связь (04.10)

Плашка «связь пропала», если две сборки подряд не пришли: сборка раз в `tick_s` (5 с), значит `now − built_ts > 2 × tick_s`
(у страницы с чужими часами — `built_ts` не менялся между двумя опросами подряд).

## Вопрос с ответом по умолчанию (04.10)

`ask.py new … --default a` → у вопроса `default` (ключ варианта, иначе `null`). В показе этот вариант помечен «(предлагаю)»,
Enter / кнопка «Ок» отвечает им (`ask.py answer <id> <default>`); у вопроса без `default` — только явный выбор варианта.
