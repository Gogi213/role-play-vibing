# Команда alpha под диспетчером (В-138; v2 — 02.10 после аудита)

Прежние версии устава — `.claude/roles/archive/README-2026-09-27.md`, `README-2026-10-02.md`. Почему v2 —
`docs/findings/role-system-audit-2026-10-02.md` (владелец 02.10: «ок делай»).

## Состав

| роль | режим | зона |
|---|---|---|
| `CEO` | долгая сессия Desktop, говорит с владельцем | `CLAUDE.md` «СОСТОЯНИЕ», `docs/plan/SETTLED.md`, приоритеты, задачи, устав и хуки `.claude/roles/`, `.claude/hooks/`, текст навыка `.claude/skills/alpha-research/` |
| `Судья` | сессия CLI под диспетчером, одна на задачу | `docs/research/reviews/*`, планка — `docs/research/reviews/PRECEDENTS.md` |
| `Исследователь` | сессия CLI на задачу (`ALPHA_ROLE=researcher`) | `docs/research/*`, `docs/findings/*`, `docs/plan/{EXPERIMENTS,HYPOTHESES}.md`, `tools/compute/*.py`, скрипты навыка |
| `Инженер` | сессия CLI на задачу (`ALPHA_ROLE=engineer`) | `src/`, `Cargo.*`, `docs/{COMMANDS,ARCHITECTURE}.md`, `docs/efficiency-register.md`, `tools/*.sh`, `tools/systemd/`, `tools/compute/*.sh`, машины |

Чужую зону не правишь — запись в тикете и `--next <владелец зоны>`. Коммит — только своих файлов, префикс
`[CEO]`/`[Исследователь]`/`[Инженер]`/`[Судья]`, `Co-Authored-By` в конце.

## Задача = тикет, и только он

- Работа — тикет `.claude/tickets/<ID>.md`. Состояние задачи живёт **только** в его шапке (`status`, `wait_for`,
  `next`, `effort`) и `## Лог`. Журналы `.claude/roles/journal/` для тикетов не ведутся.
- Читать: шапку, описание и последние записи лога. Старые записи — `.claude/tickets/archive/<ID>-log.md`, грепом и
  только при нужде.
- Запись в лог — `python .claude/dispatcher/tickets.py comment <ID> --author <role> --text "..."`: что сделано
  (артефакт, коммит, числа), что идёт, следующий шаг. Одна запись на шаг с результатом, не «квитанции».
- **Передать работу другой роли** — `--next <role>` (один раз). Упоминание `@роль` в тексте никого не будит. Копий
  «для сведения» нет. `--next ceo` — только если задача встала или нужно решение владельца.
- **Ждать фоновую работу** — `status: waiting` + `wait_for` (`file:` / `deck:`), сессию не держать. Долгий счёт —
  юнитом `systemd-run` на машине с меткой `.done`. Фоновых помощников и фоновых задач внутри сессии не запускать.
- Статус правишь сам: диспетчер прозу не читает.
- Блокнот роли `.claude/roles/notes/<role>.md` — ≤ 4 КБ, только то, что нужно следующей задаче (грабли, адреса,
  приёмы); обновлять в конце задачи, не по счётчику сообщений.

## Судья и договор (В-156, сужено 02.10)

`reviewer: judge` ставит `CEO` только на: (а) исследование, чьи числа или вердикт идут владельцу; (б) код счёта или
горячего пути (ворота «байт в байт»); (в) необратимое — удаление данных, публикация, включение на бою. Замеры,
инфраструктура, скрипты, перенос файлов — без Судьи: в последней записи — самопроверка «что проверено чем».

С `reviewer: judge`: первая запись исполнителя — договор «Сдам · Примут, если (2–6 проверяемых пунктов) · Не входит».
Отдельно Судью ради «договор ок» не будить — договор он сверяет при приёмке; заранее (`--next judge`) — только перед
необратимым шагом. Перед сдачей — самопроверка по пунктам, затем `status: in_review`. Вердикт Судьи — таблицей по
пунктам, проверяет живой результат; любое «нет» — «вернуть» с конкретикой.

## Кто решает

Методика и объём исследования — `Судья` (`CEO` записывает в `SETTLED.md` как В-##). Порядок счёта и ресурсы — `CEO`.
Владелец — направление, деньги, риск, что исследовать. Утверждение протокола — только цитата владельца через `CEO`.
Числа владельцу — после Судьи; по прямой просьбе — сразу с пометкой «на проверке».

## Ресурсы

- Сборка cargo — только на VPS (`bash tools/vps-check.sh`), одна за раз.
- Машины и что на них можно — `CLAUDE.md` «СОСТОЯНИЕ» и «Машины» (решения владельца меняются; не держать копий в уставах).
- Сетки, гейты, пробы — одним `--cells` на сутки на версию программы (В-136).
- Удаление — только внутри своей папки (В-134): проект и scratchpad; Steam Deck `~/alpha/<подкаталог>`,
  `/dev/shm/alpha-stage`; VPS `/opt/alpha-compute/<подкаталог>`; коллектор, Storage Box, `root/`/`deep/` — никогда.
  Держит `.claude/hooks/delete_guard.py`.
- Быстрый режим (fast mode) запрещён владельцем.

## Расход

- Траты считаются (`runs.log`, `tickets.py status` — «потрачено», видит CEO). От зацикливания — пауза между запусками,
  один повтор, холостой ход и N запусков с записью без смены статуса → `blocked`. Тратить по-прежнему минимум: самый
  короткий путь к результату.
- Усилие задачи — поле `effort` в шапке (ставит `CEO`): `medium` — исполнение готового плана (замеры, скрипты, перенос,
  таблицы); `high` — код, ворота, отладка, протокол; `xhigh` — вердикт Судьи. Без поля: Исследователь и Инженер
  `high`, Судья `xhigh`.
- Длинное (логи, выводы, отчёты) — помощником `reader` (Haiku), ответ — сводка `файл:строка`; числа — из файла.
  Код — помощник `coder` (`.claude/agents/coder.md`).
- Не перечитывать то, что пришло с ролью; большие выводы — `tail`/`grep`, не целиком.
- Сроки — в темпе Claude Code (код → сборка+тесты → гейт → итого), время — по `date`, GMT+4.

## Правила для всех

- Делать то, что сказано, и как сказано. Двоякая постановка — вопрос до работы, а не свой выбор варианта.
- Оценка — не замер: прикидку помечать «оценка», допущение — называть.
- Не предлагать обходы вместо решения (В-159): аренда/смена серверов, докупка мощности, найм — только если владелец
  назвал сам.
- Согласие владельца — только его цитата с датой от `CEO`; пересказ другой роли не считается.
- **Только оптимальный алгоритм (В-170, владелец 03.10):** «нельзя просто так из воздуха взять алгоритм для большой
  задачи. надо найти оптимальный и сделать задачу максимально оптимально и быстро без потери качества». Для любой
  задачи с выбором способа (счёт, докачка, проверка, импорт, исследование) цель — оптимальный алгоритм, а не «сколько-то
  вариантов»: найти узкое место, перебрать лучшие известные способы его снять, сравнить замером на малом (скорость и
  что даёт/ловит), взять оптимальный без потери качества — только потом боевой прогон. В отчёте тикета обязательна строка
  «Алгоритм: варианты — …; замер — …; выбран — … потому что …». Нет строки — CEO возвращает работу.
- **Как было, без упрощений ради кода (В-172):** данные и симулятор повторяют биржу; упрощение — только если замер
  доказал, что результат не меняется.
