Запусти диспетчер и сторож текущего проекта в фоне. Если они уже запущены (pid-замок) — они будут остановлены и
запущены заново: так подхватывается обновлённый плагин. Одной командой Bash, из корня проекта:

```
python "${CLAUDE_PLUGIN_ROOT}/.claude/dispatcher/start.py" && python "${CLAUDE_PLUGIN_ROOT}/.claude/dispatcher/supervise.py" --install
```

Второй шаг — присмотр ОС (критерий 10 «работа без владельца»): планировщик ОС раз в 5 мин проверяет, живы ли диспетчер
и сторож, и поднимает упавшие (Windows — Планировщик заданий, Linux — systemd --user timer, macOS — launchd).
Повторный запуск задачу планировщика перезаписывает, не множит. Снять — `supervise.py --uninstall`.

Скрипт сам находит корень проекта (ближайший каталог вверх с `.claude/roles`; можно добавить `--project <путь>`),
запускает `dispatch.py` и `watch.py` из папки плагина с `--project <проект>` отвязанными от сессии (Windows — WMI, вне
job-объекта приложения; Linux с systemd — юнит `systemd-run --user`; иначе отдельной сессией процесса) и печатает pid,
«отвязан: да/нет» и путь лога каждого: `<проект>/.claude/dispatcher/dispatch.run.log` и
`watch.run.log`. Нет `.claude/roles` — отказ с подсказкой `/rpv-init`.

- `${CLAUDE_PLUGIN_ROOT}` пуст (путь не подставился) — найди каталог плагина `role-play-vibing` под
  `~/.claude/plugins` (в нём `.claude/dispatcher/start.py`) и подставь его.
- Нет команды `python` — `python3` или `py -3`.

Потом ответь владельцу коротко: pid диспетчера и сторожа, «отвязан» да или нет, куда пишутся логи, был ли перезапуск,
присмотр ОС поставлен или нет (не поставлен — последняя строка ошибки).
Линукс: чтобы юниты пережили выход из системы — `loginctl enable-linger $USER`. Код возврата не 0 —
процесс упал сразу: покажи последние строки соответствующего лога.
